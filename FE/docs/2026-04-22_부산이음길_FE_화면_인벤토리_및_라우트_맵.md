# 부산이음길 FE 화면 인벤토리 및 라우트 맵

- 작성일: 2026-04-22
- 대상: 부산이음길 Android FE 구현 / route 설계 / 화면 범위 고정
- 범위: 현재 워크스페이스의 `FE/app`, `FE/docs`, `FE/mockup`에서 확인 가능한 화면만 정리

## 1. 문서 개요

### 문서 목적

- FE 개발팀이 현재 기준에서 실제로 존재하는 화면 단위를 빠르게 파악할 수 있게 한다.
- `route`, `진입/이탈`, `상태`, `파라미터`, `공통 컴포넌트`를 기준으로 구현 착수용 IA를 고정한다.
- 바이브 코딩이나 AI 보조 구현 시 문서에 없는 화면을 임의로 만들지 않도록 화면 경계를 명시한다.

### 분석 기준

- 사용자 요청 우선순위를 그대로 적용했다.
  - 1순위: 실제 코드에 존재하는 `screen / route / viewmodel / nav graph`
  - 2순위: `FE/docs/2026-04-22_부산이음길_FE_디자인_컨벤션.md`
  - 3순위: `FE/docs/2026-04-21_S14P31E102-211_공통_UI_접근성_Figma_handoff.md`
  - 4순위: `FE/docs/2026-04-13_부산이음길_FE_컴포넌트_가이드.md`
  - 5순위: `FE/docs/2026-04-13_부산이음길_FE_코드_컨벤션.md`
- `FE/mockup`은 화면 존재 여부, 화면 명칭, 단계 흐름, CTA를 보강하는 용도로 사용했다.
- 공공서비스형 지도 앱이라는 맥락을 반영해 `권한`, `오프라인`, `경로 실패`, `상태 전달`은 보수적으로 정리했다.
- 문서와 코드가 충돌하면 코드 기준을 우선하고, 코드와 목업/문서가 충돌하면 `정합성 확인 필요 항목`에 분리했다.

## 3. 화면 인벤토리 상세

### `ONB-01` 장애 유형 선택

| 항목 | 내용 |
| --- | --- |
| 화면 ID | `ONB-01` |
| 화면명 | 장애 유형 선택 |
| route / route key | `onboarding/type` (`OnboardingRoute.DisabilityType.route`) |
| 목적 | 앱의 기본 안내 모드를 `시각장애` 또는 `보행약자` 기준으로 고정한다. |
| 사용자가 이 화면에서 하는 일 | 유형 카드 선택, `다음` CTA 활성화 후 다음 단계 이동 |
| 진입 조건 | 저장된 `disabilityType` 없음 |
| 진입 경로 | 앱 시작 시 `resolveAppStartDestination()` -> `DisabilityTypeStep` |
| 이탈 경로 | `다음` -> `ONB-02` |
| 상단 구조(App Bar 패턴) | `OnboardingStepScaffold` 기반 진행률 + 제목 + 설명 |
| 하단 구조 | 고정 Primary CTA `다음`, Bottom Navigation 없음 |
| 핵심 컴포넌트 | `OnboardingStepScaffold`, `OnboardingSelectionCard`, `OnboardingModeCard` |
| 필요한 데이터 | `selectedType` 로컬 UI state |
| 필요한 파라미터 | 없음 |
| 주요 상태 | `default`: 선택 전<br/>`loading`: 해당 없음<br/>`empty`: 해당 없음<br/>`error`: 해당 없음<br/>`permission denied`: 해당 없음<br/>`completed`: 유형 선택 후 `다음` 활성화 |
| 접근성/모드 차이 | `시각장애` 선택 시 voice guide 지원 후속 분기 설명 카드 노출 |
| 구현 메모 | ViewModel 없이 `Route` 내부 `rememberSaveable`로 선택 상태 관리 |
| 근거 수준 | `코드 기준 확인` + `관찰 사실` |

### `ONB-02` 장애 등급 선택

| 항목 | 내용 |
| --- | --- |
| 화면 ID | `ONB-02` |
| 화면명 | 장애 등급 선택 |
| route / route key | `onboarding/level/{disabilityType}` (`OnboardingRoute.DisabilityLevel.route`) |
| 목적 | 안내 강도와 가독성 수준을 확정한다. |
| 사용자가 이 화면에서 하는 일 | 등급 선택, 시각장애 유형인 경우 음성 안내 미리보기 토글, `다음` |
| 진입 조건 | `disabilityType` 선택 완료 |
| 진입 경로 | `ONB-01` -> `OnboardingRoute.DisabilityLevel.createRoute(disabilityType)` |
| 이탈 경로 | `다음` -> `ONB-03` |
| 상단 구조(App Bar 패턴) | 진행률 + 제목 + 설명 + 조건부 top action(`음성 안내 보기/숨기기`) |
| 하단 구조 | 고정 Primary CTA `다음`, Bottom Navigation 없음 |
| 핵심 컴포넌트 | `OnboardingStepScaffold`, `OnboardingSummaryCard`, `OnboardingSelectionCard`, `OnboardingModeCard` |
| 필요한 데이터 | `disabilityType`, `selectedLevel`, `isVoiceGuideExpanded` |
| 필요한 파라미터 | `disabilityType`: 필수, `String`, route param. 누락/오류 시 `VISUAL_IMPAIRMENT` fallback (`코드 기준 확인`) |
| 주요 상태 | `default`: 등급 미선택<br/>`loading`: 해당 없음<br/>`empty`: 해당 없음<br/>`error`: 해당 없음<br/>`permission denied`: 해당 없음<br/>`completed`: 등급 선택 후 `다음` 활성화 |
| 접근성/모드 차이 | `disabilityType.supportsVoiceGuide == true`일 때만 음성 안내 미리보기 영역 사용 |
| 구현 메모 | `disabilityType`가 화면 구조를 직접 바꾼다. visual / mobility 분기는 이후 route 설계의 기준값이다. |
| 근거 수준 | `코드 기준 확인` + `관찰 사실` |

- 코드 기준
  - 하단 탭은 `TopLevelDestination.entries`에 포함된 route에서만 보인다.
  - `navigateToTopLevel()`로 `launchSingleTop + restoreState + popUpTo(startDestination)`를 사용한다.
  - `search`, `route_setting`, `report`, `navigation_guidance`, onboarding route에서는 탭을 숨긴다.
- 목업 기준
  - 지도 메인에서 검색/마이로 직접 이동한다.
  - 길안내와 제보는 탭이 아니라 CTA/FAB로 노출된다.

### 9.5 FE가 먼저 고정해야 하는 네비게이션 결정 5~10개

1. 루트 탭을 코드 기준 `3탭`으로 유지할지, 문서 가정 `5탭`으로 재구성할지 결정해야 한다.
2. `SAVE-01`의 위치를 `top-level route`로 볼지, `MYP-01` 하위 screen으로 볼지 결정해야 한다.
3. `REPORT-01` 진입점을 `MAP-01` FAB, `NAV-01` overlay, 별도 탭 중 어디로 고정할지 정해야 한다.
4. `FAC-01`을 계속 지도 바텀시트로 유지할지, 독립 route로 승격할지 정해야 한다.
5. 목적지 handoff 표준을 `PlaceDestination` 저장소 공유 방식으로 계속 갈지, route param 기반으로 바꿀지 정해야 한다.
6. `ROUTE-01` -> `NAV-01` handoff를 shared ViewModel로 유지할지, serializable route payload로 바꿀지 정해야 한다.
7. `NAV-01` 완료/우회/오류 상태를 route 분기 없이 동일 screen state로 유지할지 결정해야 한다.
8. `REPORT-01` 완료 이벤트의 실제 후속 화면 또는 복귀 정책을 확정해야 한다.
9. `VIS-01` ~ `VIS-04`를 onboarding의 visual mode와 어떻게 연결할지 nav graph 레벨에서 정해야 한다.
10. 위치 선택기와 사진 선택기를 system flow로 볼지, 앱 내부 화면으로 확장할지 결정해야 한다.
