## 3. 최종 정합성 결론

| 항목 | 최종 기준 |
| --- | --- |
| 앱 진입 gate | 기존 회원 `authSession -> selectedPrimaryUserType 홈 분기`, 신규 사용자 `signupToken -> 온보딩 -> POST /auth/signup` |
| 인증 화면 | `AUTH-001` 로그인만 사용한다. 현재 FE 온보딩 기준선에 별도 프로필 완료 전용 gate는 포함하지 않는다. |
| 온보딩 1단계 | `ONB-001 사용자 유형 1차 선택` |
| 1차 분기 | `저시력자` / `보행약자` |
| 저시력자 분기 | `ONB-002 저시력자 전용 후속 화면`으로 이동한 뒤 `ONB-004`로 연결한다. |
| 보행약자 분기 | `ONB-003 보행약자 2차 선택`으로 이동한다. 선택지는 `전동휠체어 사용자`, `수동휠체어 사용자`, `기타 보행약자`다. |
| 약관/동의 | `ONB-004 약관/동의`에서 법적 동의 항목을 받는다. |
| OS 권한 | `ONB-004`에서 사용자가 `다음`을 누른 뒤 다음 단계에서 `OS 위치 권한 시스템 팝업`을 띄운다. 법적 동의와 시스템 권한은 같은 단계로 합치지 않는다. |
| 튜토리얼 | 위치 권한 응답 이후 `ONB-005 튜토리얼`로 이동하고, 완료 후 `selectedPrimaryUserType`에 따라 `LV-HOM-01` 또는 `MAP-01`로 진입한다. |
| 마이페이지 재진입 | `MYP-01`의 사용자 유형 변경은 `ONB-001`부터 다시 시작한다. |
| VIS 레거시 | `VIS-*`는 현재 MVP 메인 라우트가 아니며, 저시력자 메인 분기를 대체하지 않는다. 후속 접근성 확장 참고만 허용한다. |

## 5. 오픈 이슈

| 항목 | 내용 |
| --- | --- |
| 저시력자 후속 화면 상세 UI | `ONB-002`의 상세 선택 요소와 저장 스키마는 문서 근거가 더 필요하다. 현재는 화면 존재, 진입, 완료, 다음 단계 연결까지만 기준선으로 확정한다. |
| 사용자 유형 저장 매핑 | FE 상태 `selectedPrimaryUserType`은 서버 `users.selectedPrimaryUserType`에 저장한다. FE 상태 `selectedMobilitySubtype`은 `selectedPrimaryUserType=MOBILITY_IMPAIRED`일 때만 서버 `users.selectedMobilitySubtype`에 저장하고, `LOW_VISION`이면 받지 않는다. |
| 약관 저장 정책 | 필수 약관 동의는 회원가입 완료 조건으로 확인하고 서버 `users` 별도 필드로 저장하지 않는다. |

## 6. 주의 사항

- `개인위치정보 수집·이용 동의`는 `ONB-004`의 법적 동의 항목이다.
- `OS 위치 권한 허용`은 `ONB-004` 다음 단계의 시스템 팝업이다.
- 문서에서 두 개념을 같은 문장이나 같은 단계 의미로 합쳐 쓰지 않는다.
- `저시력자`는 후속 확장 후보가 아니라 현재 온보딩 1차 분기의 한 축이다.
