# 관리자 로컬 현황 및 운영 전환 정리

> **작성일:** 2026-05-09  
> **작성자:** AI

---

## 1. 목적

관리자 화면은 보행 네트워크 검수, 편의시설 확인, 사용자 도로 상태 제보 검토를 위한 운영 도구다.

이 문서는 현재 로컬에서 동작하는 관리자 구성과, 이후 dev/prod 운영 환경으로 전환할 때 확인해야 할 항목을 정리한다.

---

## 2. 현재 구현 상태

### 2.1 접속 경로

현재 관리자 화면은 BE 정적 리소스로 빌드되어 아래 경로에서 접근한다.

```text
http://localhost:8080/admin-web/
```

개발 중 Vite dev server를 직접 띄우는 경우에는 `http://localhost:3001`도 사용할 수 있지만, 로컬 통합 검수 기준은 `8080/admin-web`이다.

관리자 빌드 명령:

```powershell
cd ADMIN
npm run build:be-static
```

빌드 결과는 아래에 생성된다.

```text
BE/src/main/resources/static/admin-web
```

Spring forward controller가 `/admin-web`, `/admin-web/` 요청을 `/admin-web/index.html`로 전달한다.

### 2.2 인증 및 권한

관리자 화면은 진입 전에 로그인 화면을 먼저 보여준다.

지원 방식:

```text
Kakao 로그인
Naver 로그인
Google 로그인
로컬 테스트용 accessToken 직접 입력
```

소셜 로그인 흐름:

```text
1. 관리자 화면에서 소셜 제공자 accessToken 발급
2. BE /auth/social-login 호출
3. 서비스 accessToken 발급
4. /admin/me 호출
5. users.role = ADMIN 이면 관리자 화면 진입
```

권한 기준:

```text
users.role = USER | ADMIN
```

가입 기본값은 `USER`이고, 관리자는 DB에서 `ADMIN`으로 승격된 사용자만 통과한다.

로컬에서 특정 사용자를 관리자로 승격하는 예:

```sql
update users
set role = 'ADMIN',
    updated_at = now()
where user_id = '사용자 UUID';
```

### 2.3 백엔드 보안

현재 `/admin/**` API는 `ROLE_ADMIN`으로 보호된다.

기준:

```text
/admin, /admin/** -> hasRole("ADMIN")
```

`JwtAuthenticationFilter`는 accessToken의 userId로 사용자를 조회하고, DB의 `users.role`이 `ADMIN`이면 `ROLE_ADMIN` 권한을 부여한다.

주의:

```text
토큰 자체에 role을 넣는 방식이 아니다.
따라서 DB role 변경이 다음 요청부터 바로 반영된다.
대신 관리자 API 요청마다 사용자 role 조회가 필요하다.
```

### 2.4 로컬 OAuth 설정

관리자 화면은 `/auth/test-config`에서 테스트용 소셜 로그인 설정을 읽는다.

필요 설정:

```text
AUTH_TEST_KAKAO_JAVASCRIPT_KEY
AUTH_TEST_NAVER_CLIENT_ID
AUTH_TEST_GOOGLE_CLIENT_ID
auth.test.enabled=true
```

로컬에서 소셜 로그인을 쓰려면 각 제공자 콘솔에 현재 관리자 origin/callback이 등록되어 있어야 한다.

현재 로컬 통합 기준:

```text
origin: http://localhost:8080
redirect URI: http://localhost:8080/admin-web/
backend: http://localhost:8080
```

확인된 오류 유형:

```text
Kakao KOE004/KOE009: 카카오 앱 설정, 도메인, redirect URI 문제
Google origin_mismatch: Authorized JavaScript origins 미등록
Naver callback 오류: Callback URL 미등록
Kakao Map SDK 로드 실패: Maps JavaScript SDK용 앱 키 또는 Web platform 도메인 미등록
```

이 오류들은 대부분 코드 문제가 아니라 제공자 콘솔 등록 문제다.

### 2.5 지도 SDK

관리자 지도는 Kakao Map SDK를 사용한다.

필요 설정:

```text
VITE_KAKAO_MAP_KEY
```

주의:

```text
소셜 로그인용 Kakao JavaScript 키와 지도 SDK에 사용하는 키가 다를 수 있다.
지도 SDK 키에는 http://localhost:8080 같은 관리자 origin이 Web platform 도메인으로 등록되어 있어야 한다.
```

`Kakao Map SDK 로드 실패`가 발생하면 먼저 카카오 개발자 콘솔에서 아래를 확인한다.

```text
1. VITE_KAKAO_MAP_KEY가 실제 Kakao JavaScript 키인지
2. Maps JavaScript SDK 사용이 가능한 앱인지
3. Web platform 도메인에 http://localhost:8080이 등록되어 있는지
```

### 2.6 관리자 지도 데이터

관리자 지도는 CSV 서버가 아니라 BE DB 조회 API를 사용한다.

주요 API:

```text
GET /admin/areas
GET /admin/road-network/segments
GET /admin/places/facilities
```

사용 테이블:

```text
admin_areas
road_segments
road_nodes
places
place_accessibility_features
```

관리자 화면은 BE에서 받은 GeoJSON 형태의 payload를 지도에 렌더링한다.

주의:

```text
CSV 편집 서버는 운영 의존성이 아니다.
운영 기준은 ADMIN -> BE /admin/** -> DB 구조다.
```

### 2.7 제보 검토

관리자 화면에서 사용자 도로 상태 제보를 조회하고 승인/반려할 수 있다.

주요 API:

```text
GET /admin/hazard-reports
GET /admin/hazard-reports/{reportId}
PATCH /admin/hazard-reports/{reportId}/approve
PATCH /admin/hazard-reports/{reportId}/reject
```

사용자용 제보 API와 관리자 검토 API는 분리되어 있다.

```text
사용자: /hazard-reports/**
관리자: /admin/hazard-reports/**
```

## 3. 로컬 실행 기준

### 3.1 BE 실행

로컬 통합 기준은 BE가 `8080`에서 실행되는 상태다.

필수 확인:

```text
http://localhost:8080/admin-web/
http://localhost:8080/auth/test-config
```

`/auth/test-config`가 404 또는 403이면 `auth.test.enabled` 설정을 확인한다.

### 3.2 관리자 로그인

권장 흐름:

```text
1. http://localhost:8080/admin-web/ 접속
2. Kakao/Naver/Google 중 하나로 로그인
3. 가입이 필요한 계정이면 먼저 회원가입 완료
4. DB에서 해당 userId를 ADMIN으로 승격
5. 다시 로그인하거나 새 accessToken 발급
6. /admin/me 통과 확인
```

로컬 테스트용 accessToken 입력은 소셜 로그인 설정이 막혔을 때만 사용한다.

주의:

```text
accessToken은 발급한 BE의 JWT issuer/secret과 현재 호출하는 BE 설정이 같아야 한다.
dev 서버에서 받은 토큰을 local 서버에 넣으면 401이 날 수 있다.
accessToken은 만료 시간이 짧으므로 오래된 토큰은 다시 발급받아야 한다.
```

### 3.3 401/403 점검 순서

401이면 인증 자체가 실패한 것이다.

```text
1. accessToken이 비어 있지 않은지
2. Bearer prefix가 중복으로 들어가지 않았는지
3. 토큰 exp가 지나지 않았는지
4. 토큰 issuer가 현재 BE 설정과 같은지
5. 현재 ADMIN이 호출하는 backend URL이 토큰 발급 서버와 같은지
```

403이면 인증은 되었지만 관리자 권한이 없는 것이다.

```sql
select user_id, social_provider, provider_user_id, role
from users
where user_id = '사용자 UUID';
```

## 4. 운영 전환 시 필요한 작업

### 4.1 배포 경로 결정

현재 구조는 BE 정적 리소스 `/admin-web/`에 관리자 화면을 포함한다.

운영에서도 이 구조를 유지할지, 별도 관리자 도메인으로 분리할지 결정해야 한다.

후보:

```text
https://api.dev.busaneumgil.com/admin-web/
https://dev.busaneumgil.com/admin-web/
https://admin.dev.busaneumgil.com
https://admin.busaneumgil.com
```

현재 구현은 `window.location.origin`을 기본 backend로 쓰므로, BE 정적 서빙 방식이면 CORS 부담이 작다.
별도 관리자 도메인을 쓰면 CORS 허용 origin을 반드시 설정해야 한다.

### 4.2 OAuth 제공자 콘솔 등록

운영 관리자 주소가 확정되면 Kakao/Naver/Google 콘솔에 등록해야 한다.

등록 대상:

```text
관리자 origin
관리자 redirect URI
Kakao Map SDK Web platform domain
```

예시:

```text
origin: https://api.dev.busaneumgil.com
redirect URI: https://api.dev.busaneumgil.com/admin-web/
```

정확한 값은 최종 배포 경로에 맞춰야 한다.

### 4.3 auth-test 설정

현재 관리자 화면은 `/auth/test-config`에서 소셜 로그인 키를 읽는다.

운영에서 이 방식을 그대로 쓸지는 별도 결정이 필요하다.

안전한 운영 방향:

```text
dev: auth.test.enabled=true 허용 가능
prod: auth.test.enabled=false 권장
prod 관리자 로그인 설정은 별도 admin auth config로 분리
```

단, prod에서 `/auth/test-config`를 끄면 관리자 화면도 별도 설정 공급 방식을 가져야 한다.

### 4.4 관리자 계정 관리

초기에는 DB에서 최초 관리자 1명을 수동 승격할 수 있다.

운영 장기 방향:

```text
관리자 목록 조회
사용자 검색
USER -> ADMIN 승격
ADMIN -> USER 회수
권한 변경 감사 로그
```

감사 로그에는 최소한 아래 정보가 필요하다.

```text
작업자 userId
대상 userId
변경 전 role
변경 후 role
변경 시각
사유
```

### 4.5 운영 DB 데이터

관리자 지도 기능을 운영에서 사용하려면 운영 DB에 검수 대상 데이터가 적재되어야 한다.

필수 검증:

```text
admin_areas row count
road_segments row count
road_nodes row count
places row count
place_accessibility_features row count
geometry SRID
geometry index
구/동별 조회 성능
```

운영 적재 전에는 백업과 rollback 방법을 준비해야 한다.

## 6. 현재 결론

현재 관리자 기능은 로컬 검수 기준으로는 동작 가능한 상태다.

현재 기준:

```text
ADMIN 접속: http://localhost:8080/admin-web/
인증: 소셜 로그인 또는 로컬 accessToken 입력
권한: users.role = ADMIN
지도 데이터: BE /admin/** DB 조회
제보 검토: BE /admin/hazard-reports/**
```

운영 전환에서 가장 중요한 미정 항목은 배포 경로와 OAuth/Kakao Map SDK 콘솔 등록값이다.
이 값이 확정되지 않으면 로그인과 지도 SDK가 코드와 무관하게 실패할 수 있다.
