## 1. 프로젝트 개요

### 프로젝트 한 줄 정의

부산 지역 이동 약자를 위한 무장애(Barrier-Free) 길찾기 모바일 서비스

### 추진 배경

부산시는 언덕, 계단, 복잡한 지형이 많아 휠체어 이용자, 고령자, 유아차 동반 시민 등 이동 약자에게 특히 불편한 도시 구조를 가지고 있다. 기존 네이버·카카오맵 등의 길찾기 서비스는 일반 보행자 기준으로 경로를 제공하며, 무장애 이동 경로에 대한 정보가 부재하거나 부정확하다. 관광 중심의 무장애 정보 서비스는 존재하지만, 부산 시민의 일상 이동을 충분히 지원하지 못한다.

### 해결하려는 문제

이동 약자가 처음 가는 장소로 이동할 때 경사, 계단, 단차, 엘리베이터 부재 등의 장벽 정보를 사전에 파악할 수 없다. 기존 길찾기 앱은 휠체어 통행 가능 여부, 경사도, 베리어프리 시설 위치를 고려하지 않으며, 시각장애인을 위한 음성 기반 경로 안내도 지원하지 않는다. 현장 장애물(공사, 점자블록 손상 등)에 대한 실시간 정보 공유 체계도 부재한다.

### 프로젝트 목적

부산 내 무장애 이동 경로 데이터베이스를 구축하고, 이동 약자 맞춤 경로 탐색 기능을 제공한다. 시민 참여형 장애물 정보 업데이트 체계를 마련하고, 부산시 교통·복지 정책과의 연계 기반을 만든다.

### 기대 효과

이동 약자가 안전하고 독립적으로 부산 곳곳을 이동할 수 있게 된다. 장벽 없이 연결되는 도시 인프라 정보가 축적되고, 수집된 경로 데이터가 장기적으로 도시 접근성 개선에 기여한다.

## 2. 서비스 대상 및 사용자 정의

### 핵심 사용자(타깃)

장애 유형은 **시각장애**와 **보행약자** 두 가지로 분류한다.

시각장애에는 시각장애인이 해당한다. 보행약자에는 휠체어 이용자(전동/수동), 고령자, 유아차 동반 보호자, 일시적 이동 불편자(골절·수술 후 회복 중인 시민)가 포함된다.

일반 보행자는 서비스 대상에서 제외한다. 부산이음길은 교통약자 전용 접근성 길찾기 서비스로 정의하며, 범용 길찾기 모드는 제공하지 않는다.

### 사용자 특성

시각장애인은 음성 안내와 점자블록 정보가 필수이며, LLM 기반 대화형 UI를 통해 앱을 조작한다. 휠체어 이용자는 경사로와 엘리베이터가 있는 경로가 필수이고, 전동휠체어 충전소 정보를 필요로 한다. 고령자는 계단과 경사면 이동에 어려움이 있으며, 큰 글씨와 간결한 UI가 필요하다. 유아차 동반 보호자는 단차와 계단 회피 경로를 필요로 한다.

### 주요 문제 상황(Pain Point)

경사, 단차, 접근성 부족, 정보 부재가 반복적으로 발생한다. 처음 가는 장소의 휠체어 접근 가능 여부를 사전에 알 수 없다. 엘리베이터 고장, 도로 공사 등 현장 변수에 대응할 정보가 없다. 기존 앱은 정보가 부정확하거나 UI가 복잡하며, 한 손 조작이 어렵고 글자가 작다.

### 사용 맥락

부산 지역 내 일상 이동(통원, 출퇴근, 장보기 등)이 주요 사용 맥락이다. 혼자 이동하는 상황과 보호자 동반 이동 모두를 고려한다. 필드트립 조사에서 확인한 바와 같이, 이용자는 복지관 담당자에게 이동 경로를 문의하거나 지인 경험에 의존하는 경우가 많다.

## 3. 서비스 핵심 가치

### 서비스가 제공하는 핵심 가치

이동 약자가 계단, 급경사, 단차를 회피하고 경사로, 엘리베이터, 자동문이 있는 경로를 우선 안내받을 수 있다. 시각장애인은 음성 대화만으로 목적지를 설정하고 경로 안내를 받을 수 있다. 현장의 장애물 상황을 시민이 직접 제보하여 실시간으로 정보를 갱신할 수 있다.

### 기존 방식 대비 차별점

일반 길찾기 앱은 보행자 최단 경로만 제공하지만, 부산이음길은 무장애 경로를 우선 탐색한다. 관광 중심 무장애 서비스와 달리, 시민의 일상 이동에 초점을 맞춘다. 부산의 지형 특성(경사, 언덕)에 특화된 경사도 기반 경로 추천을 제공한다. 시민 참여형 제보 체계를 통해 정보의 최신성을 유지한다.

### 사용자 관점 효익

보행약자 관점에서는 안전하고 편안한 이동 경로를 사전에 확인할 수 있어 독립적 외출이 가능해진다. 시각장애인 관점에서는 음성만으로 앱을 조작할 수 있어 별도 도움 없이 길찾기가 가능하다. 베리어프리 시설(음식점, 관광지, 화장실, 충전소) 정보를 한곳에서 확인할 수 있다.

## 4. 서비스 범위

### 4.1 포함 범위

MVP는 Android 앱을 기준으로 한다. 언어는 한국어를 지원한다.

MVP 기준 필수 기능은 다음과 같다: 위치정보 이용약관 동의, 온보딩(장애유형·등급 선택), 현재 위치 표시, 베리어프리 시설 마커 표시, 점자블록 위치 표시, 시설 유형 필터, 텍스트 기반 목적지 검색, 무장애 경로 안내(경사로·엘리베이터·자동문 우선, 계단·급경사 회피), 음성 안내(TTS), 사용자 경로 데이터 수집, 자주 가는 길 저장, 도로 상태 제보, 저장한 장소 관리이다.

우선 제공 대상은 부산 지역 내 MVP 대상 구역이며, 대상 구역은 별도 확정이 필요하다.

### 4.2 제외 범위

이번 단계에서 제외되는 기능(선택 기능으로 분류)은 다음과 같다: 회원가입/로그인(비로그인으로 모든 기본 기능 이용 가능), 음성 검색(STT), 최근 검색 기록, 경로 이탈 시 재탐색, 저상버스 정보 조회, 장애인 콜택시(두리발) 호출, 사용자 정보 수정, 설정 화면, 시각장애인 전용 UI(LLM 대화형 인터페이스, 리스트 기반 화면, TalkBack 지원, 음성 브리핑), 지도 확대/축소/이동 조작이다. 사용자별 제보 조회/상세/수정/삭제는 익명 제보 정책으로 제공하지 않는다.

후속 단계 검토 기능(2차 개발 고려)은 다음과 같다: 웨어러블 연동(Galaxy Watch), 주변 장소 추천, AI 챗봇(맛집·관광지 추천), 캐릭터 UI(날씨 연동), 커뮤니티(사용자 간 정보 공유), 응급 도움 요청(원터치 긴급 호출), iOS 앱, 영어·일어 다국어 지원이다.

## 5. 핵심 사용자 흐름

### 서비스 진입

앱 최초 설치 시 온보딩 → 위치정보 이용약관 동의 → 로그인(선택) → 지도 메인 화면 순서로 진행한다. 앱 재실행 시 바로 지도 메인 화면으로 진입한다.

### 온보딩/초기 설정

SCR-001에서 장애유형(시각장애/보행약자)을 선택한다. 선택 즉시 해당 UI 모드(TTS, 고대비 등)가 반영된다. SCR-002에서 장애등급 또는 필요한 지원 수준을 선택한다. 온보딩 선택은 필수이며, 범용 길찾기 모드는 제공하지 않는다. 온보딩 설정은 로그인 없이도 로컬에 저장된다.

### 위치정보 동의 및 로그인

SCR-003에서 위치정보 이용약관에 필수 동의한다. 필수 항목 미동의 시 앱 종료 또는 기능 제한 모드로 진입한다. SCR-004에서 소셜 로그인(카카오, 네이버, 구글) 또는 지문인식을 할 수 있다. 비로그인으로 계속하기를 선택하면 로컬 저장 모드로 서비스를 이용한다.

### 핵심 기능 사용 흐름 (보행약자 경로 안내)

지도 메인(SCR-006)에서 검색창을 탭하여 SCR-008에서 목적지를 검색한다. 검색 결과를 선택하면 지도에 위치가 표시된다. 내비게이션 버튼 또는 시설 상세 팝업(SCR-007)의 길안내 버튼을 탭하면 SCR-009 경로 설정 화면으로 이동한다. 출발지(기본: 현재 위치)와 목적지를 확인하고 경로를 탐색한다. 경사로·엘리베이터·자동문 포함 경로를 우선 제공한다. 경로 시작 버튼을 탭하면 SCR-010에서 실시간 내비게이션이 시작되고 TTS 음성 안내가 진행된다.

### 핵심 기능 사용 흐름 (시각장애인 음성 경로 안내)

설정에서 시각장애 모드를 선택하면 SCR-016 시각장애인 모드 메인으로 진입한다. 대화형 AI 버튼을 탭하면 SCR-017 LLM 대화형 UI로 이동한다. 음성 입력 버튼을 탭하고 "OOO로 가고 싶어"라고 말하면 STT로 텍스트 변환 후 LLM이 의도를 파악한다. LLM이 "도착지가 OOO 맞나요?"로 TTS 확인 후 사용자가 "네"라고 응답하면 SCR-010에서 자동으로 경로 안내가 시작된다.

### 제보 흐름

지도 메인(SCR-006)에서 제보 버튼을 탭하면 SCR-011로 이동한다. 제보 유형(도로 공사/장애물/점자블록 손상/기타)을 선택하고, 위치(자동 연동, 핀 드래그로 조정 가능)와 사진(최대 3장, 선택), 설명을 입력한다. 제보 제출 시 지도에 임시 마커가 생성되고 관리자 검토 후 반영 또는 민원 연결된다.

### 예외/실패/권한 미동의 시 흐름

위치정보 약관 미동의 시 앱 종료 또는 기능 제한 모드로 진입한다. 위치 권한 미허용 시 현재 위치 표시와 경로 안내가 불가능하다. STT/TTS/LLM 연동 실패 시 텍스트 검색 및 기본 안내 플로우로 fallback한다. 경로 이탈 시 자동 재탐색을 실행하고 재탐색 중 음성/자막 안내를 제공한다. 앱 삭제 후 재설치 시 SCR-001부터 재진행하며 위치정보 재동의가 필요하다.

## 6. 기능 정의

### 6.1 앱 초기 설정

**기능 목적:** 사용자 맞춤 UI 제공을 위한 초기 설정과 법적 필수 동의를 수집한다.

**상세 기능 목록:**

위치정보 이용약관 동의(필수): 앱 설치 시 1회 필수로 위치정보 이용약관 동의를 받는다. 로그인 여부와 무관하며, 앱 삭제 후 재설치 시 재동의가 필요하다. 법적 필수 사항이며 서비스 이용의 전제 조건이다.

온보딩(필수): 첫 접속 사용자에게 장애유형(시각장애/보행약자) 선택 화면을 제공한다. 이어서 장애등급 또는 필요한 지원 수준을 선택받는다. 선택 즉시 해당 UI 모드가 적용된다. 범용 길찾기 모드는 제공하지 않으며, 로그인 없이도 로컬에 저장된다.

**동작 조건:** 앱 최초 설치 후 자동 표시. 온보딩 완료 후 위치정보 동의 → 로그인 화면 순서로 진행한다.

**예외 처리:** 필수 약관 미동의 시 앱 종료 또는 기능 제한 모드 진입.

**관련 화면:** SCR-001(장애유형 선택), SCR-002(장애등급 선택), SCR-003(위치정보 이용약관 동의)

### 6.2 유저 정보

**기능 목적:** 회원 관리 및 데이터 동기화를 제공한다. 회원가입은 선택 사항이며, 비로그인 상태에서도 모든 기본 기능을 이용할 수 있다.

**상세 기능 목록:**

회원가입(선택): 닉네임(필수, 실명 대신 사용), 장애유형(필수), 장애등급(온보딩 선택값 자동 입력), 전화번호(선택, 미입력 시 119 기본 설정)를 입력한다. 닉네임 중복 확인을 지원한다.

로그인(선택): 소셜 로그인(카카오, 네이버, 구글)을 지원한다. 지문인식을 통한 기기 내 사용자 식별이 가능하다(로그인 없이도). 로그인 시 북마크, 자주 가는 길 등의 데이터가 DB에 저장되며, 비로그인 시 로컬 스토리지에만 저장된다.

로그아웃(선택): 로그아웃 시 로컬 데이터는 유지된다.

회원탈퇴(선택): 탈퇴 시 모든 저장 데이터가 삭제된다. 재가입은 가능하지만 기존 데이터 복구는 불가하다.

**관련 화면:** SCR-004(로그인), SCR-005(회원가입), SCR-013(마이페이지)

### 6.3 지도 (메인)

**기능 목적:** 사용자 현재 위치와 주변 베리어프리 시설 정보를 지도에 시각화하고, 주요 기능의 진입점을 제공한다.

**상세 기능 목록:**

현재 위치 표시(필수): 앱 실행 시 사용자의 현재 위치를 지도에 표시한다. 위치 권한 허용 시에만 작동하며 실시간으로 업데이트된다.

베리어프리 시설 정보 표시(필수): 음식점(베리어프리 인증), 관광지(베리어프리 인증), 장애인 화장실, 엘리베이터, 전동휠체어 충전소의 위치를 시설별 다른 아이콘 마커로 표시한다. 마커 탭 시 하단 슬라이드업 팝업(SCR-007)으로 상세정보(이름, 주소, 유형, 베리어프리 시설 목록—경사로·자동문·엘리베이터 등, 운영시간)를 표시한다.

점자블록 위치 표시(필수): 점자블록 위치를 별도 아이콘 마커로 표시한다. 데이터는 수집 예정이다.

필터 기능(필수): 음식점, 관광지, 화장실, 엘리베이터, 충전소 유형별 필터 칩을 제공한다. 다중 선택이 가능하며, 필터 적용 시 해당 유형 마커만 표시된다.

지도 확대/축소/이동(선택): 핀치 제스처로 확대/축소, 드래그로 이동, 내 위치 버튼으로 현재 위치 복귀를 지원한다.

**입력값:** GPS 좌표(현재 위치), 필터 선택값

**출력값:** 지도 뷰, 시설 마커, 시설 상세 팝업

**관련 화면:** SCR-006(지도 메인), SCR-007(시설 상세 팝업)

### 6.4 검색

**기능 목적:** 사용자가 텍스트 또는 음성으로 목적지를 검색하고 빠르게 접근할 수 있게 한다.

**상세 기능 목록:**

텍스트 검색(필수): 장소명, 주소 입력으로 목적지를 검색한다. 검색 결과 리스트(이름, 주소, 현재 위치 기준 거리)를 표시하며 부산 지역 우선 검색한다. 검색 결과 선택 시 지도에 해당 위치를 표시한다.

음성 검색(선택): 시각장애인 모드에서 STT 기반 음성 검색을 지원한다. 마이크 버튼 터치로 시작/종료하며, 인식된 텍스트로 자동 검색을 실행한다. 표준어 기반 인식이며 사투리 인식은 추후 고려한다.

최근 검색 기록(선택): 최근 검색 장소를 최대 10개까지 로컬에 저장한다. 개별 삭제와 전체 삭제를 지원한다.

**관련 화면:** SCR-008(검색)

### 6.5 내비게이션

**기능 목적:** 이동 약자가 안전하게 이동할 수 있는 최적 경로를 탐색하고 실시간 안내를 제공한다.

**상세 기능 목록:**

경로 안내(필수): 출발지(기본: 현재 위치)와 도착지를 설정하면 보행약자 이용 가능한 최적 경로를 안내한다. 경사로, 엘리베이터, 자동문이 있는 경로를 우선하고 계단, 급경사를 회피한다. 예상 소요 시간을 표시하고 경로를 지도에 시각적으로 표시한다. 경로 옵션으로 최단거리와 베리어프리 우선 경로 선택을 제공한다. 자주 가는 길 저장 기능을 함께 제공한다.

음성 안내—TTS(필수): 내비게이션 중 "100미터 전방에서 좌회전하세요" 등 구체적 음성 경로 안내를 제공한다. 음성 안내 ON/OFF 설정이 가능하다.

경로 이탈 시 재탐색(선택): 안내 경로 이탈 시 자동으로 경로를 재탐색한다. 재탐색 중 음성 및 자막 안내를 제공한다.

**동작 조건:** 휠체어 최적 경로 알고리즘과 도로 경사도 데이터가 필요하다.

**관련 화면:** SCR-009(경로 설정), SCR-010(내비게이션 진행)

### 6.6 경로 수집

**기능 목적:** 사용자 동의 하에 실제 이동 경로를 수집하여 서비스 개선과 경로 최적화에 활용한다.

**상세 기능 목록:**

사용자 경로 데이터 수집(필수): 사용자 동의 하에 GPS 좌표, 이동 시간, 장애 유형을 수집한다. 설정에서 데이터 수집 ON/OFF가 가능하다. 수집 데이터는 익명화 처리한다.

자주 가는 길 저장(필수): 자주 이용하는 경로를 저장하고 빠른 검색을 지원한다. 로그인 시 DB 저장, 비로그인 시 로컬 저장이다.

**관련 화면:** SCR-008(검색 화면 내 자주 가는 길 섹션), SCR-009(경로 설정 화면 내 저장 버튼), SCR-015(설정 화면 내 데이터 수집 동의 토글)

### 6.7 제보/신고

**기능 목적:** 사용자 참여형으로 현장 장애물 정보를 수집하고 지도에 반영하여 정보의 최신성을 유지한다.

**상세 기능 목록:**

도로 상태 제보(필수): 도로 공사, 장애물, 점자블록 손상 등을 제보한다. 제보 시 위치(자동 연동, 핀 드래그 조정 가능), 제보 유형(필수), 사진(최대 3장, 선택), 설명(선택)을 입력한다. 제보는 사용자 계정과 연결하지 않는 익명 제보로 저장한다. 제보 내용은 지도에 임시 마커로 표시되며, 관리자 검토 후 반영 또는 민원 연결한다.

**관련 화면:** SCR-011(도로 상태 제보)

### 6.8 교통정보 연계

**기능 목적:** 대중교통 접근성 정보를 연계하여 이동 약자의 이동 선택지를 넓힌다.

**상세 기능 목록:**

저상버스 정보 조회(선택): 주변 저상버스 노선 정보, 실시간 도착 정보, 운행 시간표를 제공한다. 공공 데이터 활용 여부 사전 조사가 필요하다.

장애인 콜택시 호출—두리발(선택): 앱 내에서 두리발(장애인 이동서비스) 외부 전화 연결을 제공한다.

**관련 화면:** SCR-006(지도 메인 내 저상버스 정보 버튼, 두리발 호출 버튼)

### 6.9 마이페이지

**기능 목적:** 사용자의 개인화 데이터(저장 장소)와 계정 정보를 관리한다.

**상세 기능 목록:**

저장한 장소 관리(필수): 북마크한 장소 목록 확인, 개별 삭제, 해당 장소로 길안내 시작을 지원한다.

사용자 정보 수정(선택): 닉네임, 장애 유형, 등급, 전화번호를 수정할 수 있다.

설정(선택): 장애 모드 변경(시각장애/보행약자, 즉시 UI 전환), 음성 안내 ON/OFF, 데이터 수집 동의 ON/OFF, 알림 설정, 앱 버전 정보, 개인정보처리방침 링크를 포함한다.

**관련 화면:** SCR-013(마이페이지), SCR-014(저장한 장소 관리), SCR-015(설정)

### 6.10 시각장애인 전용 UI

**기능 목적:** 시각장애인이 음성과 간결한 인터페이스만으로 서비스를 이용할 수 있게 한다.

**상세 기능 목록:**

대화형 LLM 인터페이스(선택): STT + LLM + TTS 통합 방식으로 동작한다. 음성 입력("OOO로 가고 싶어") → LLM 의도 파악 → TTS 확인 질문 → 사용자 확인 → 자동 경로 안내 시작의 흐름이다. 대화 히스토리를 관리하며 자연어 이해와 대화 맥락을 유지한다.

리스트 기반 화면 구성(선택): 지도 대신 장소 목록을 리스트 형식으로 제공한다. 최소 폰트 18pt, 버튼 최소 60×60pt, 노란색 계열 배경색, 화면당 최대 3개 버튼으로 구성한다.

TalkBack 지원(선택): 모든 UI 요소에 접근성 라벨을 지정하고 화면 읽기 순서를 최적화한다. Android TalkBack을 기준으로 접근성을 보장한다.

음성 브리핑 강화(선택): 내비게이션 시작 전 전체 경로 음성 브리핑("총 거리 500미터, 예상 시간 10분, 좌회전 2회, 우회전 1회" 등)을 제공한다. 브리핑 재생/일시정지 기능을 포함한다.

**관련 화면:** SCR-016(시각장애인 모드 메인), SCR-017(LLM 대화형 UI)

## 7. 화면 구성

### 전체 화면 목록

총 16개 화면으로 구성된다.

SCR-001 온보딩 – 장애유형 선택, SCR-002 온보딩 – 장애등급 선택, SCR-003 위치정보 이용약관 동의, SCR-004 로그인, SCR-005 회원가입, SCR-006 지도 메인, SCR-007 시설 상세 팝업, SCR-008 검색, SCR-009 내비게이션 경로 설정, SCR-010 내비게이션 진행, SCR-011 도로 상태 제보, SCR-013 마이페이지, SCR-014 저장한 장소 관리, SCR-015 설정, SCR-016 시각장애인 모드 메인, SCR-017 LLM 대화형 UI

### 화면별 목적 및 주요 UI 요소

**SCR-001 온보딩 – 장애유형 선택:** 장애유형(시각장애/보행약자)을 선택하여 맞춤 UI를 결정하는 첫 화면이다. 진행 표시기(1/3), 안내 문구, 시각장애/보행약자 선택 카드, 다음 버튼으로 구성된다. 관련 기능: 0-2

**SCR-002 온보딩 – 장애등급 선택:** 장애등급 또는 필요한 지원 수준을 선택하여 접근성 세부 수준을 조정한다. 진행 표시기(2/3), 등급 또는 지원 수준 선택 리스트, 음성 안내 버튼(시각장애 모드 시), 다음 버튼으로 구성된다. 관련 기능: 0-2

**SCR-003 위치정보 이용약관 동의:** 법적 필수 위치정보 동의를 수집한다. 약관 본문 스크롤, 전체 동의/개별 동의 체크박스, 동의하고 시작 버튼, 나중에 하기 버튼으로 구성된다. 관련 기능: 0-1

**SCR-004 로그인:** 소셜 로그인 또는 비로그인 진행을 선택한다. 카카오/네이버/구글 로그인 버튼, 지문인식 버튼, 비로그인으로 계속 버튼, 회원가입 링크로 구성된다. 관련 기능: 1-2

**SCR-005 회원가입:** 소셜 로그인 최초 시도 시 추가 정보를 입력한다. 닉네임 입력(중복 확인), 장애유형 선택, 장애등급 확인/수정, 전화번호 입력(선택)으로 구성된다. 관련 기능: 1-1

**SCR-006 지도 메인:** 앱의 핵심 화면. 지도 뷰, 현재 위치/시설 마커, 검색창, 필터 칩, 내 위치 FAB, 내비게이션 시작 FAB, 제보 FAB, 하단 내비게이션 바(지도/검색/마이페이지), 저상버스 정보 버튼, 두리발 호출 버튼으로 구성된다. 관련 기능: 2-1, 2-2, 2-3, 2-4, 2-5

**SCR-007 시설 상세 팝업:** 시설 마커 탭 시 하단 슬라이드업 팝업. 시설명, 유형 배지, 주소, 베리어프리 시설 태그, 운영시간, 북마크 버튼, 길안내 버튼으로 구성된다. 관련 기능: 2-2

**SCR-008 검색:** 목적지를 텍스트/음성으로 검색한다. 텍스트 검색 입력창, 음성 검색 버튼, 검색 결과 리스트, 최근 검색 기록(최대 10개), 자주 가는 길 섹션으로 구성된다. 관련 기능: 3-1, 3-2, 3-3

**SCR-009 내비게이션 경로 설정:** 출발지/목적지를 설정하고 경로를 탐색한다. 출발지 입력(기본: 내 위치), 목적지 입력, 경로 옵션(최단거리/베리어프리 우선), 경로 탐색 버튼, 예상 경로 카드, 지도 미리보기, 경로 시작 버튼, 자주 가는 길 저장 버튼으로 구성된다. 관련 기능: 4-1

**SCR-010 내비게이션 진행:** 실시간 경로 안내 화면. 실시간 지도 뷰, 현재 안내 카드(방향 화살표+텍스트), 남은 거리/예상 도착 시간, 음성 안내 ON/OFF 토글, 전체 경로 보기 버튼, 재탐색 알림 배너, 내비게이션 종료 버튼, 경로 브리핑 버튼(시각장애인 모드)으로 구성된다. 관련 기능: 4-1, 4-2, 4-3

**SCR-011 도로 상태 제보:** 현장 장애물을 제보한다. 제보 유형 선택(필수), 위치 표시 지도(핀 드래그 조정), 사진 첨부(최대 3장), 설명 입력, 제보 제출/취소 버튼으로 구성된다. 관련 기능: 6-1

**SCR-013 마이페이지:** 개인화 메뉴를 제공한다. 프로필 영역(닉네임, 장애유형, 등급), 로그인/로그아웃 버튼, 저장한 장소/내 정보 수정 메뉴(마이페이지 내부 편집)/설정 메뉴, 앱 버전 정보, 회원탈퇴 링크로 구성된다. 관련 기능: 8-1, 8-2, 8-3

**SCR-014 저장한 장소 관리:** 북마크 장소를 관리한다. 장소 목록(이름, 주소, 유형 아이콘), 삭제(스와이프), 길안내 버튼, 빈 상태 안내로 구성된다. 관련 기능: 8-1

**SCR-015 설정:** 앱 전반의 사용자 설정을 관리한다. 장애 모드 전환(시각장애/보행약자), 음성 안내 토글, 데이터 수집 동의 토글, 알림 설정 토글, 앱 버전 정보, 개인정보처리방침 링크로 구성된다. 관련 기능: 8-3

**SCR-016 시각장애인 모드 메인:** 지도 대신 리스트 기반 구성. 대화형 AI 버튼(노란색, 60×60pt 이상), 주변 장소 리스트(큰 폰트 최소 18pt), 검색 버튼, 마이페이지 버튼, 최대 3개 버튼 레이아웃, 고대비 노란색 계열 배경으로 구성된다. 관련 기능: 9-1, 9-2, 9-3

**SCR-017 LLM 대화형 UI:** 음성으로 목적지를 설정하고 대화를 통해 경로 안내를 시작한다. 음성 입력 버튼(큰 원형, 노란색, 화면 중앙), 대화 내용 표시(큰 폰트), 음성 파형 표시, LLM 응답 자동 TTS 재생, 확인/취소 버튼으로 구성된다. 관련 기능: 9-1

메인 탭 네비게이션: SCR-006(지도) ↔ SCR-008(검색) ↔ SCR-013(마이페이지)

## 8. 정책 및 운영 규칙

### 서비스 정책

비로그인 상태에서도 모든 기본 기능(지도 조회, 검색, 경로 안내, 제보)을 이용할 수 있다. 로그인 시 북마크, 자주 가는 길 등의 데이터가 클라우드(DB)에 동기화되며, 비로그인 시 로컬에만 저장된다(앱 삭제 시 데이터 손실). 닉네임은 개인정보 보호를 위해 실명 대신 사용한다. 전화번호는 응급상황 대비 용도이며, 미입력 시 119가 기본 설정된다.

### 권한/동의/알림 관련 규칙

위치정보 이용약관 동의는 앱 설치 시 1회 필수이며, 앱 삭제 후 재설치 시 재동의가 필요하다. 위치 권한이 허용된 경우에만 현재 위치 표시와 경로 안내가 작동한다. 경로 데이터 수집은 사용자 동의 하에만 수행되며 설정에서 ON/OFF 가능하다. 수집된 데이터는 익명화 처리한다.

### 상태값/분기 처리 규칙

장애 모드는 시각장애와 보행약자 두 가지이며, 온보딩 시 선택하거나 설정에서 변경할 수 있다. 시각장애 모드 선택 시 즉시 TTS, 고대비, 큰 폰트 등의 UI가 적용된다. 보행약자 모드 선택 시 이동 지원 중심 UI가 적용된다. 북마크는 로그인 여부에 따라 DB 또는 로컬에 저장된다. 제보 처리 상태는 검토중, 처리완료, 반려의 3단계이다.

### 검증 규칙

닉네임 중복 여부를 실시간으로 확인한다. 회원가입 시 닉네임과 장애유형은 필수, 전화번호는 선택이다. 제보 제출 시 제보 유형 선택은 필수이다. 경로 탐색 시 출발지와 목적지 모두 입력되어야 경로 탐색 버튼이 활성화된다.

### 예외 상황 처리 기준

STT/TTS/LLM 연동 실패 시 텍스트 검색 및 기본 안내 플로우로 fallback한다. 경로 이탈 시 자동 재탐색을 실행하고 재탐색 중 음성/자막으로 안내한다. 외부 API 또는 네트워크 장애 시 목업 데이터와 캐시 데이터로 핵심 기능이 동작하도록 구성한다. 제보 제출 실패 시 완료 알림 대신 오류 안내를 표시한다. 검색 결과가 없을 경우 빈 상태 안내를 표시한다. 저장 장소가 없을 경우 빈 상태 안내와 지도 탐색 유도를 제공한다.

## 9. 데이터 및 연동 개요

### 내부적으로 다루는 주요 데이터

사용자 데이터: 닉네임, 장애유형, 장애등급, 전화번호, 북마크 장소, 자주 가는 길, 검색 기록(로컬)

경로 수집 데이터: GPS 좌표, 이동 시간, 장애 유형(익명화)

제보 데이터: 위치, 제보 유형, 사진, 설명, 처리 상태

### 외부 연동 요소

부산시 보도 GIS 데이터(폭, 경사도, 포장 상태), 부산시 엘리베이터·경사로 위치 DB, 베리어프리 음식점·관광지 데이터(무장애부산관광 연계), 저상버스 노선 및 정류장 데이터, 공공 화장실·장애인 화장실 위치, 전동휠체어 충전소 위치, 점자블록 위치(수집 예정)

소셜 로그인 OAuth(카카오, 네이버, 구글), 지도 SDK(최종 확정 필요), STT/TTS 서비스, LLM API(서버 탑재 또는 API 연동)

### 데이터 연계 기관

부산광역시 스마트시티혁신과, 부산교통공사, 국토교통부 국가공간정보포털, 한국장애인개발원, 무장애부산관광

### 데이터 흐름 개요

사용자 앱 → 백엔드 API(경로 탐색, 시설 조회, 제보 등록, 회원 관리) → DB(MySQL). 경로 탐색 시 경사도 데이터와 시설 위치 데이터를 조합하여 무장애 경로를 산출한다. 시각장애인 모드에서는 사용자 음성 → STT → LLM(의도 파악) → 경로 탐색 API → TTS 경로 안내 흐름으로 동작한다. 사용자 제보는 서버에 전송되어 관리자 검토 후 지도 데이터에 반영된다.

### 문서에 명시된 제약사항

점자블록 데이터는 수집 예정 상태이며 현재 확보되지 않았다. 공공 데이터의 정합성 문제가 존재할 수 있으며, 부산 전역이 아닌 우선 지역으로 범위를 축소하고 시연용 시드 데이터를 직접 구축할 필요가 있다. 저상버스 공공 데이터 활용 가능 여부는 사전 조사가 필요하다.

## 10. 비기능 요구사항

### 성능

경로 탐색 응답 5초 이내, 시설 검색/조회 3초 이내 동작을 목표로 한다.

### 보안/개인정보

위치 정보를 암호화하고 개인정보보호법을 준수한다. 경로 수집 데이터는 익명화 처리한다. 닉네임 사용으로 실명 노출을 방지한다.

### 접근성

WCAG 2.1 AA 등급 준수를 목표로 한다. 핵심 화면에 TalkBack 접근성 라벨을 적용하고, 주요 버튼 크기 60×60pt 이상을 확보한다. 시각장애인 모드에서 최소 폰트 18pt, 고대비 노란색 계열 배경, 화면당 최대 3개 버튼 구성을 적용한다. Android TalkBack 기준 점검을 수행한다.

### 안정성

서비스 가동률 99% 이상을 목표로 한다. 외부 API 또는 네트워크 의존성에 대비하여 목업 데이터와 캐시 데이터를 준비하고 데모 환경에서도 핵심 기능이 동작하도록 구성한다. STT/TTS/LLM 실패 시 텍스트 기반 fallback을 제공한다.

### 운영 및 유지보수 고려사항

공공 데이터 부족 또는 정합성 문제에 대비하여 우선 지역으로 범위를 축소하고 시드 데이터를 직접 구축한다. 사용자 제보 데이터의 검증 체계(관리자 검토 후 반영)를 운영한다. 필수 기능 우선순위를 고정하고 선택 기능은 단계적으로 제외 가능한 구조로 관리한다. 와이어프레임 단계부터 접근성 체크리스트를 적용하고, 구현 후 TalkBack 중심 점검을 수행한다.

## 11. 역할 관점 정리

### 기획 관점 핵심 포인트

장애유형은 시각장애와 보행약자 두 가지로 통일한다. 모든 기본 기능은 비로그인 상태에서도 이용 가능해야 한다. MVP 범위는 필수 기능에 집중하되, 선택 기능은 구조적으로 분리하여 단계적 추가가 가능해야 한다. 필드트립(함세상장애인자립생활센터 인터뷰)에서 확보한 현장 인사이트를 경로 알고리즘과 UI 설계에 반영해야 한다. 시연 시나리오 3개(전동휠체어 경로 안내, 시각장애인 음성 탐색, 도로 상태 제보)를 end-to-end로 완성해야 한다.

### 디자인 관점 핵심 포인트

시각장애 모드와 보행약자 모드의 UI가 장애유형 선택 즉시 분기되어야 한다. 시각장애인 모드는 지도 대신 리스트 기반, 최소 18pt 폰트, 60×60pt 이상 버튼, 노란색 계열 고대비, 화면당 최대 3개 버튼으로 구성한다. 시설 마커는 유형별 아이콘을 구분하여 디자인한다. 시설 상세 팝업은 하단 슬라이드업 형태이다. 모든 UI 요소에 TalkBack 접근성 라벨을 제공해야 한다.

### 프론트엔드 관점 핵심 포인트

Kotlin + Jetpack 기반 Android 앱으로 구현한다. 지도 SDK 연동과 마커 오버레이, 필터 토글, 실시간 위치 추적이 핵심이다. 소셜 로그인 OAuth(카카오, 네이버, 구글)와 지문인식 연동이 필요하다. 온보딩에서 선택한 장애유형/등급에 따른 UI 모드 즉시 전환 로직을 구현해야 한다. 로그인/비로그인 상태에 따른 데이터 저장 분기(DB vs 로컬)를 처리해야 한다. TalkBack 접근성 라벨과 포커스 순서 최적화가 필요하다.

### 백엔드 관점 핵심 포인트

Java + Spring Boot 기반, MySQL DB를 사용한다. 메시지 큐는 RabbitMQ를 사용한다. 핵심 API: 회원 관리(가입, 로그인, 정보 수정, 탈퇴), 시설 조회/검색, 경로 탐색(무장애 경로 알고리즘), 북마크 CRUD, 제보 등록/조회/상태 관리, 경로 데이터 수집/저장이다. 소셜 로그인 OAuth 서버 사이드 처리가 필요하다. 공공 데이터 연동과 데이터 갱신 체계를 구축해야 한다.

### 데이터/AI 관점 핵심 포인트

경로 데이터 가공: 부산시 보도 GIS 데이터(경사도, 폭, 포장 상태)를 경로 탐색 알고리즘에 반영한다. 경사로, 엘리베이터, 계단 데이터를 경로 그래프에 통합한다. STT/TTS 검증: 음성 인식과 음성 합성의 정확도와 응답 속도를 검증한다. 표준어 기반이며 사투리 대응은 추후 고려한다. LLM 연동: 시각장애인 대화형 UI를 위한 LLM 모델(서버 탑재 또는 API 연동)의 의도 파악 정확도와 대화 맥락 유지를 검증한다. 수집 경로 데이터의 익명화 처리 및 경로 최적화 분석에 활용한다.

## 12. 향후 과제

### 현재 문서 기준 미정 항목

지도 SDK와 경로 탐색 방식의 최종 조합이 확정되지 않았다. 부산 지역 내 MVP 대상 구역 및 데이터 수집 범위가 확정되지 않았다. 접근성 점검 기준과 테스트 체크리스트가 문서화되지 않았다. 최종 발표용 시연 시나리오와 실패 대응 플로우가 상세화되지 않았다.

### 후속 검토 필요 항목

공공 데이터(엘리베이터 위치, 경사로, 장애인 화장실 등)의 실제 정합성 검증이 필요하다. 점자블록 데이터 수집 방법과 일정을 확정해야 한다. 저상버스 공공 데이터 API 활용 가능 여부를 조사해야 한다. 사용자 제보 데이터의 허위 정보 대응 정책을 수립해야 한다. 필드트립 인터뷰 결과를 경로 알고리즘 파라미터(경사도 허용 기준, 보행로 최소 폭, 턱 허용 높이 등)에 반영해야 한다.

### 확장 가능 기능

웨어러블 연동(Galaxy Watch), 주변 장소 추천, AI 챗봇(맛집·관광지 추천), 캐릭터 UI, 커뮤니티, 응급 도움 요청, iOS 앱, 영어·일어 다국어 지원

## 13. 문서 정합화 결과

### 이번 정리로 확정한 항목

**플랫폼 범위:** MVP 플랫폼은 Android 앱으로 한정한다. iOS 앱은 확장 가능 기능으로 유지한다.

**온보딩과 위치약관 동의 순서:** 초기 진입 흐름은 온보딩(SCR-001, SCR-002) → 위치약관 동의(SCR-003) → 로그인(SCR-004) → 지도 메인(SCR-006) 순서로 확정한다.

**마이페이지 내 정보 수정 처리:** 내 정보 수정은 SCR-013 마이페이지 내부 편집으로 정리한다. SCR-016은 시각장애인 모드 메인 화면으로 유지한다.

**MVP 범위 관리 원칙:** 4.1/4.2의 포함 범위와 제외 범위를 현재 기준으로 유지한다. 비MVP 기능의 상세 설명은 문서 내에 남겨두되, 구현 범위 판단은 4.1/4.2를 우선 기준으로 삼는다.

### 정보가 불충분한 항목

지도 SDK 선정(네이버 지도, 카카오맵, Google Maps 등) 및 무장애 경로 탐색 알고리즘의 구체적 설계가 문서에 없다. 경사도 데이터를 경로 추천에 어떻게 반영할지(가중치, 임계값 등)의 기술 설계가 없다. 접근성 등급의 산정 기준(필드트립에서 수집할 예정이나 아직 미확정)이 없다. 제보 데이터의 관리자 검토 프로세스(검토 주체, 검토 주기, 반려 기준 등)가 구체화되지 않았다. LLM 모델 선정 및 서버 탑재/API 방식의 결정이 미확정이다.

### 추가 문서 정리 예정 항목

화면명세서는 현재 MVP와 비MVP 화면이 함께 기술되어 있으므로, 추후 MVP 화면과 확장 기능 화면을 분리해 정리한다. 최종 발표용 시연 시나리오 3개의 상세 플로우와 실패 대응 문구는 별도 시연 문서로 정리한다.
