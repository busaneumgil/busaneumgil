## 1. 제품 개요

### 1.1 한 줄 정의

부산이음길은 보행약자가 부산 지역에서 목적지까지 이동할 때 접근성 정보, 경로 비교, 장애물 제보를 하나의 흐름에서 확인할 수 있도록 돕는 무장애 길안내 서비스다.

### 1.2 해결하려는 문제

- 기존 길찾기 서비스는 일반 보행자 기준이어서 경사, 계단, 단차, 엘리베이터, 공사/통제 같은 이동 장벽을 경로 선택 기준으로 충분히 반영하지 못한다.
- 보행약자는 처음 가는 목적지에서 접근 가능한 시설과 실제 이동 위험 요소를 동시에 파악하기 어렵다.
- 현장 장애물 정보는 빠르게 변하지만 사용자 제보와 경로 탐색 흐름이 분리되어 있으면 반영 속도가 떨어진다.

### 1.3 제품 목표

| 목표 | 설명 |
| --- | --- |
| 접근 가능한 길찾기 | `안전한 길`, `최단거리` 2개 경로 옵션으로 빠르게 경로를 비교하게 한다. |
| 일관된 진입 경험 | `AUTH-001 -> ONB-001~ONB-005 -> MAP-01` 기준의 필수 로그인 + 온보딩 흐름을 유지한다. |
| 제보와 길찾기 연결 | `REPORT-01`~`REPORT-04` 제보 플로우와 `MYP-02` 제보 내역을 일관되게 연결한다. |
| 문서/제품 정합성 | 화면 ID, 용어, CTA, 데이터 책임, MVP 범위를 문서 전반에서 동일하게 유지한다. |

## 2. 타겟 사용자와 용어

| 구분 | 기준 |
| --- | --- |
| 서비스 상위 사용자 용어 | `보행약자` |
| 세부 이동 특성 | `휠체어 사용자 (전동)`, `휠체어 사용자 (수동)`, `기타 보행약자` |
| 포함 예시 | 전동/수동 휠체어 사용자, 보행 보조기구 사용자, 고령자, 유아차 동반 보호자, 일시적 이동 불편자 |
| 후속 접근성 확장 | 음성 중심 전용 흐름, 시각 지원 전용 `VIS` 흐름, LLM UI는 후속 확장 후보로 둔다. |

`장애등급`은 온보딩 필수 단계에서 제거한다. 기존 서버 필드와의 매핑은 `BE 확인 필요`다.

## 3. 제품 원칙

| 항목 | 원칙 |
| --- | --- |
| 앱 진입 gate | `authSession -> onboardingCompleted -> MAP-01` 순서로 분기한다. 인증 세션이 없으면 `AUTH-001`로 이동한다. |
| 로그인 정책 | 카카오/네이버/구글 소셜 로그인만 제공한다. production 기준 `비로그인으로 계속`, guest mode, 비로그인 핵심 기능 사용은 제거한다. |
| 온보딩 정책 | 온보딩은 `ONB-001`~`ONB-005` 5단계다. `SCR-001`~`SCR-003`, `ONB-01`~`ONB-03` 같은 구 구조는 폐기한다. |
| 화면 구조 | 하단 탭은 `홈 / 북마크 / 제보 / 마이페이지` 4탭으로 고정한다. |
| 경로 구조 | `ROUTE-01`은 경로 지도/탐색 결과, `ROUTE-02`는 경로 상세, `NAV-01`은 길안내 진행 화면으로 분리한다. |
| 경로 옵션 | 사용자 노출 경로 옵션은 `안전한 길`, `최단거리` 2개만 사용한다. |
| 북마크 정책 | 사용자 노출 명칭은 `북마크`다. `BMK-01`은 장소 탭, `BMK-02`는 경로 탭이다. |
| 제보 정책 | 제보는 `REPORT-01`~`REPORT-04` 4단계 플로우다. 제보는 사용자 계정과 연결하며 처리 상태는 FE에 노출하지 않는다. |
| 데이터 책임 | 서버 데이터가 기준이며 로컬은 `cache/offline/pending` 보조 역할로만 사용한다. |
| 미확정 처리 | 화면, 정책, API, enum, 저장 위치가 불명확하면 추정하지 않고 `미확정`, `TBD`, `BE 확인 필요`로 남긴다. |

## 4. MVP 범위

### 4.1 포함 범위

| 영역 | 화면 ID | 포함 내용 |
| --- | --- | --- |
| 인증 | `AUTH-001` | 필수 소셜 로그인 |
| 온보딩 | `ONB-001`~`ONB-005` | 서비스 소개, 사용자 유형 선택, 권한 안내, 약관 동의, 서비스 소개 슬라이드 |
| 지도 홈 | `MAP-01`, `FAC-01` | 검색바, STT 진입 버튼, 접근성 필터, 시설 마커/상세, 최근 목적지, 하단 4탭 |
| 목적지 설정 | `DEST-01`~`DEST-04` | 검색, 검색 결과, 지도/바텀시트 확인, 사용자 상태 설문 |
| 경로/길안내 | `ROUTE-01`, `ROUTE-02`, `NAV-01` | 경로 비교, 경로 상세, 실시간 길안내 |
| 도착/평가 | `ARR-01`, `ARR-02` | 도착 완료, 경로 평가, 경로 저장 |
| 북마크 | `BMK-01`, `BMK-02` | 장소/경로 북마크 조회, 삭제, 길찾기 연결 |
| 제보 | `REPORT-01`~`REPORT-04` | 유형 선택, 위치 확인, 상세 입력, 접수 완료 |
| 마이페이지 | `MYP-01`~`MYP-03` | 프로필 요약, 제보 내역, 앱 정보 및 도움말, 로그아웃/회원탈퇴 동선 |

### 4.2 제외 또는 후순위

- `비로그인으로 계속`, guest mode, 데모 모드 기반 메인 흐름
- `SCR-001`~`SCR-003`, `ONB-01`~`ONB-03` 같은 구 온보딩 구조
- 3탭 또는 5탭 후보 구조
- 사용자 노출 화면명으로 `저장`, `Saved`, `자주 가는 길`을 기본 명칭처럼 사용하는 정책
- 시각장애 전용 `VIS` 흐름과 LLM UI를 현재 MVP 메인 흐름으로 서술하는 정책
- 북마크 정렬, 전체 선택, 다중 선택
- 제보 처리 상태 사용자 화면
- 고객센터/1:1 문의 실제 연결
- `local-first`나 로컬 source of truth를 production 핵심 정책으로 서술하는 방식

## 5. 핵심 사용자 흐름

### 5.1 앱 진입

```text
앱 실행
  -> authSession 확인
  -> 세션 없음: AUTH-001
  -> 세션 있음 + onboardingCompleted=false: ONB-001
  -> 세션 있음 + onboardingCompleted=true: MAP-01
```

### 5.2 목적지 탐색과 길안내

```text
MAP-01 -> DEST-01 -> DEST-02 -> DEST-03 -> DEST-04(필요 시) -> ROUTE-01 -> ROUTE-02(선택) -> NAV-01 -> ARR-01 -> ARR-02
```

| 단계 | 기준 |
| --- | --- |
| 검색 결과 선택 | `DEST-02`에서 선택해도 반드시 `DEST-03` 목적지 확인을 거친다. |
| 사용자 상태 설문 | `DEST-04` 노출 조건은 미정이다. |
| 경로 비교 | `ROUTE-01`에서는 `안전한 길`, `최단거리` 2개만 비교한다. |
| 길안내 시작 | `ROUTE-01` 또는 `ROUTE-02`의 `길 안내 시작`으로 `NAV-01`에 진입한다. |
| 도착/평가 | `ARR-01` 진입 즉시 `ARR-02` 평가 모달을 자동 표시한다. |

### 5.3 북마크

```text
MAP-01 -> BMK-01 <-> BMK-02
```

| 단계 | 기준 |
| --- | --- |
| 장소 북마크 | 카드 본문은 `FAC-01`, `길찾기`는 `DEST-03` 확인 후 `ROUTE-01`로 연결한다. |
| 경로 북마크 | 카드 본문은 `ROUTE-02`, `길찾기`는 `NAV-01` 즉시 진입이다. |

### 5.4 제보

```text
MAP-01 -> REPORT-01 -> REPORT-02 -> REPORT-03 -> REPORT-04 -> MYP-02
```

| 단계 | 기준 |
| --- | --- |
| 유형 선택 | 8개 제보 유형 중 하나를 선택한다. |
| 위치 확인 | pin drag로 위치를 확정한다. |
| 상세 입력 | 사진은 갤러리/카메라 모두 허용한다. |
| 완료 | `제보 내역 확인하기`는 `MYP-02`로 연결한다. |

## 6. 기능 요구사항 요약

| 기능 영역 | 사용자 가치 | 핵심 요구사항 |
| --- | --- | --- |
| 인증 | 로그인된 사용자 기준으로 개인화와 저장 기능을 일관되게 제공한다. | `AUTH-001` 필수 로그인, 세션 유지/재발급/로그아웃 처리 |
| 온보딩 | 사용자의 이동 특성을 초기에 정리해 경로 추천 기준을 만든다. | `ONB-001`~`ONB-005` 5단계, 사용자 유형 선택, 권한 안내, 약관 동의 |
| 지도 홈 | 탐색과 주요 진입점을 하나의 홈 화면에서 제공한다. | `MAP-01` 검색, 필터, 최근 목적지, 시설 상세, 하단 4탭 |
| 목적지 설정 | 검색 결과를 바로 경로로 연결하지 않고 목적지를 확인한다. | `DEST-01`~`DEST-04`, 검색 결과 후 `DEST-03` 확인 필수 |
| 경로/길안내 | 사용자가 비교 가능한 경로 후보와 실시간 길안내를 제공한다. | `ROUTE-01`, `ROUTE-02`, `NAV-01`, 2개 경로 옵션, 재탐색 후보 |
| 도착/평가 | 도착 직후 만족도와 경로 저장을 자연스럽게 수집한다. | `ARR-01`, `ARR-02`, 자동 평가 모달, 경로 저장 |
| 북마크 | 자주 찾는 장소와 경로를 빠르게 다시 사용하게 한다. | `BMK-01`, `BMK-02`, 장소/경로 분리, 삭제만 허용 |
| 제보 | 장애물 정보를 구조화된 흐름으로 수집한다. | `REPORT-01`~`REPORT-04`, 계정 연결, 상태 미노출 |
| 마이페이지 | 계정과 사용자 상태 변경, 제보 확인, 도움말을 제공한다. | `MYP-01`~`MYP-03`, 사용자 유형 변경, 로그아웃/탈퇴 동선 |

## 7. 데이터 및 연동 책임

| 데이터 영역 | 기준 데이터 책임 | 로컬 역할 | 비고 |
| --- | --- | --- | --- |
| 인증 세션 | 서버 인증 응답 기준 | secure storage/token cache | 세션 만료, 재발급, 로그아웃 삭제 범위는 `BE 확인 필요` |
| 온보딩 완료 상태 | 서버/사용자 설정 또는 동기화 상태 기준 | 온보딩 재개용 보조 상태 | 최종 동기화 계약은 `BE 확인 필요` |
| 사용자 유형 | 서버 프로필/설정 기준 | 현재 세션 선택 상태 보조 | 기존 API `disabilityType`, `disabilityGrade`와의 매핑은 `BE 확인 필요` |
| 장소/경로 응답 | 서버 및 외부 연동 응답 기준 | 현재 세션 캐시 | 식별자, 좌표, 주소 일관성이 필요하다 |
| 북마크 장소/경로 | 서버 데이터 기준 | `cache/offline/pending` | 기존 API 명칭과 사용자 노출 용어 매핑은 `BE 확인 필요` |
| 제보 draft | 제출 전 로컬 임시 상태 | draft/pending | 제출 이후에는 서버 제보 이력이 기준이다 |
| 제보 이력 | 서버 사용자 제보 데이터 기준 | 목록 캐시 | FE에서는 처리 상태를 숨긴다 |
| 경로 평가 | 신규 서버 API 예정 | UI 임시 상태 | API 상세 미정 |

## 9. 미확정 항목

| 영역 | 내용 |
| --- | --- |
| 로그인 UX 순서 | 시스템 gate는 `authSession -> onboardingCompleted -> MAP-01`로 고정한다. 다만 `AUTH-001`과 `ONB-001`의 시각적 첫 노출 순서는 최종 UX 확정이 필요하다. |
| 권한 | `ONB-003`에서 OS 권한 실제 요청 시점은 미정이다. |
| 목적지 설문 | `DEST-04` 노출 조건과 저장 우선순위는 미정이다. |
| 길안내 종료 | `NAV-01` 중도 종료 후 이동 정책은 미정이다. |
| 경로 평가 | `ARR-02` 평가 저장 API 상세는 `BE 확인 필요`다. |
| 프로필 매핑 | `MYP-01` 프로필 필드 데이터 매핑은 미정이다. |
| 활동 배지 | `제보왕`, `도움왕`, `참여왕` 산정 기준은 미정이다. |
| 알림 | 알림 설정 노출 여부는 미정이다. |
| 로그아웃/탈퇴 | 로그아웃 시 온보딩/프로필 상태 유지 여부와 토큰 삭제 범위, 회원탈퇴 재인증 방식은 `BE 확인 필요`다. |
