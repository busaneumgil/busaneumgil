## 0. 정렬 기준

| 항목 | 최신 기준 |
| --- | --- |
| 앱 진입 gate | `authSession -> onboardingCompleted -> MAP-01` 순서로 분기한다. 인증 세션이 없으면 `AUTH-001`로 이동한다. |
| 로그인 정책 | `AUTH-001`은 필수 로그인 화면이며 카카오/네이버/구글 소셜 로그인만 제공한다. production 기준 `비로그인으로 계속`, guest mode, 비로그인 핵심 기능 사용은 제거한다. |
| 온보딩 정책 | 온보딩은 `ONB-001`~`ONB-005` 5단계다. `SCR-001`~`SCR-003`, `ONB-01`~`ONB-03`, 장애등급 필수 입력 구조는 사용하지 않는다. |
| 사용자 용어 | 서비스 상위 용어는 `보행약자`로 통일한다. 세부 이동 특성은 `휠체어 사용자 (전동)`, `휠체어 사용자 (수동)`, `기타 보행약자`다. |
| 하단 탭 | `홈 / 북마크 / 제보 / 마이페이지` 4탭으로 고정한다. |
| 경로 구조 | `ROUTE-01`은 경로 지도/탐색 결과, `ROUTE-02`는 경로 상세, `NAV-01`은 길안내 진행 화면이다. |
| 경로 옵션 | `안전한 길`, `최단거리` 2개만 사용한다. |
| 북마크 명칭 | 사용자 노출 명칭은 `북마크`로 통일한다. `BMK-01`은 장소 탭, `BMK-02`는 경로 탭이다. |
| 제보 구조 | 제보는 `REPORT-01`~`REPORT-04` 4단계 플로우다. |
| 데이터 책임 | 서버 데이터가 기준이며 로컬은 `cache/offline/pending` 보조 역할로만 사용한다. `local-first`를 production 핵심 정책으로 서술하지 않는다. |

## 1. 인증 및 온보딩

| 화면 ID | 핵심 기능 | 주요 전환 규칙 | 데이터/정책 |
| --- | --- | --- | --- |
| `AUTH-001` | 소셜 로그인으로 인증 세션을 생성한다. | 로그인 성공 후 온보딩 미완료면 `ONB-001`, 완료면 `MAP-01`로 이동한다. | 카카오/네이버/구글만 제공한다. guest mode와 비로그인 우회는 제공하지 않는다. |
| `ONB-001` | 서비스명과 무장애 길찾기 목적을 안내하고 온보딩을 시작한다. | `시작하기` 선택 시 `ONB-002`로 이동한다. | 인증 완료 후 온보딩 미완료 상태에서만 진입한다. |
| `ONB-002` | 보행약자 세부 이동 특성을 선택한다. | 사용자 유형 선택 후 `다음`으로 `ONB-003`으로 이동한다. | 선택지는 `휠체어 사용자 (전동)`, `휠체어 사용자 (수동)`, `기타 보행약자`만 사용한다. `장애등급`은 이 단계에 포함하지 않는다. |
| `ONB-003` | 위치, 마이크, 알림 관련 권한 목적을 안내한다. | 안내 확인 후 `ONB-004`로 이동한다. | 위치 권한은 필수 안내 대상이다. 마이크는 온보딩에서 요청하지 않고 STT 장소 검색 사용 시점 요청으로 정리한다. 실제 OS 권한 요청 시점은 미정이다. |
| `ONB-004` | 필수 약관 동의와 약관 전문 확인 동선을 제공한다. | 필수 약관 동의 완료 후 `ONB-005`로 이동한다. | 약관 전문은 웹뷰로 연다. URL, 버전 관리, 저장 위치는 `BE 확인 필요`다. |
| `ONB-005` | 핵심 기능 소개를 3페이지 이상 제공하고 온보딩을 완료한다. | 마지막 페이지 완료 시 `onboardingCompleted`를 저장하고 `MAP-01`로 이동한다. | 별도 가입 화면 없이 온보딩이 초기 사용자 설정 수집 역할을 맡는다. |

### 1.1 온보딩 공통 규칙

| 항목 | 기준 |
| --- | --- |
| 단계 수 | `ONB-001`~`ONB-005` 5단계로 고정한다. |
| 용어 | 화면 문구와 접근성 라벨 모두 `보행약자` 기준으로 통일한다. |
| 상태 표현 | 선택, 오류, 비활성, 완료 상태는 색상만이 아니라 텍스트와 semantics를 함께 제공한다. |
| 재진입 | `MYP-01`의 `사용자 유형 변경`은 `ONB-002`를 재사용한다. 저장 정책은 `BE 확인 필요`다. |

## 2. 지도 홈, 시설, 목적지 설정

| 화면 ID | 핵심 기능 | 주요 전환 규칙 | 데이터/정책 |
| --- | --- | --- | --- |
| `MAP-01` | 지도 홈에서 검색, 시설 탐색, 최근 목적지, 하단 4탭 진입점을 제공한다. | 검색바는 `DEST-01`, 시설 마커는 `FAC-01`, 북마크 탭은 `BMK-01`, 제보 탭은 `REPORT-01`, 마이페이지 탭은 `MYP-01`로 이동한다. | 홈 탭 활성 상태다. 위치 권한이 없으면 기능 제한 안내를 제공한다. |
| `FAC-01` | 시설 상세 바텀시트에서 시설 정보, 접근성 라벨, 북마크, 길찾기를 제공한다. | `길찾기` 선택 시 `DEST-03` 확인 후 `ROUTE-01`로 연결한다. | 지도 또는 북마크 장소 상세에서 진입한다. 북마크 저장 실패 처리와 장소 식별자 매핑은 `BE 확인 필요`다. |
| `DEST-01` | 목적지 검색과 최근 방문지 목록을 제공한다. | 검색 실행 시 `DEST-02`, 최근 방문지 선택 시 `DEST-03`, `전체보기` 선택 시 `BMK-01`로 이동한다. | 하단 탭은 유지한다. 마이크 버튼은 STT 장소 검색 진입점이다. |
| `DEST-02` | 검색 결과를 카드 목록으로 보여주고 후보를 고르게 한다. | 결과 카드 선택 시 항상 `DEST-03`으로 이동한다. | 검색 결과에서 곧바로 `ROUTE-01`에 진입하지 않는다. |
| `DEST-03` | 지도와 목적지 바텀시트로 도착지를 최종 확인한다. | `도착지로 설정` 선택 시 설문 필요 여부에 따라 `DEST-04` 또는 `ROUTE-01`로 이동한다. | 장소 식별자, 좌표, 주소를 일관되게 유지해야 한다. |
| `DEST-04` | 첫 사용 시 현재 이동 상태 설문을 제공한다. | 상태 선택 후 `ROUTE-01`로 이동한다. | 표시 조건, 저장 위치, 온보딩 사용자 유형과의 우선순위는 미정이다. |

### 2.1 지도 및 검색 공통 규칙

| 항목 | 기준 |
| --- | --- |
| 접근성 필터 | `MAP-01`은 접근성 필터를 제공한다. `더보기` 포함 항목은 미정이다. |
| 최근 목적지 | 별도 전체 목록 화면을 만들지 않고 `BMK-01`로 연결한다. |
| STT | STT 처리 주체와 서버 연동 방식은 `BE 확인 필요`다. |
| 장소 데이터 | 검색 결과와 시설 상세는 장소 식별자, 좌표, 주소를 일관되게 내려줘야 한다. |

## 3. 경로 탐색, 길안내, 도착, 평가

| 화면 ID | 핵심 기능 | 주요 전환 규칙 | 데이터/정책 |
| --- | --- | --- | --- |
| `ROUTE-01` | 경로 지도와 탐색 결과를 보여주고 경로 옵션을 비교한다. | 옵션 카드 본문 선택은 선택 상태만 변경한다. 카드 우측 상단 화살표는 `ROUTE-02`, `길 안내 시작`은 `NAV-01`로 이동한다. | `안전한 길`, `최단거리` 2개 옵션만 사용한다. 하단 탭은 숨긴다. |
| `ROUTE-02` | 선택한 경로의 단계별 상세와 주의 구간을 보여준다. | `길 안내 시작` 선택 시 `NAV-01`로 이동하고, 뒤로가기는 `ROUTE-01`로 복귀한다. | 엘리베이터, 경사, 단차, 횡단보도 같은 상세 라벨은 텍스트로 함께 제공한다. |
| `NAV-01` | 실시간 길안내 진행 상태와 다음 행동, 남은 거리/시간을 제공한다. | 상세 정보는 `ROUTE-02`, 도착 완료는 `ARR-01`로 이동한다. | 경로 이탈 시 재검색/재탐색으로 정리한다. 중도 종료 후 이동 정책은 미정이다. |
| `ARR-01` | 도착 완료를 알리고 후속 행동을 제공한다. | `홈으로 돌아가기`는 `MAP-01`, `새 경로 탐색하기`는 `DEST-01`로 이동한다. 진입 즉시 `ARR-02`를 자동 표시한다. | 홈 탭이 활성인 완료 화면이다. |
| `ARR-02` | 경로 만족도 평가와 경로 저장을 수집한다. | `평가 등록`은 평가 저장 처리, `이 경로 저장하기`는 경로 북마크 저장, `X`는 평가 건너뛰기다. | 평가 저장 API는 신규 예정 항목이다. 경로 저장 payload와 실패 처리도 `BE 확인 필요`다. |

### 3.1 경로 공통 규칙

| 항목 | 기준 |
| --- | --- |
| 경로 분리 | `ROUTE-01`, `ROUTE-02`, `NAV-01`은 서로 다른 책임을 가진다. |
| 경로 옵션 | 사용자 노출 경로 옵션은 `안전한 길`, `최단거리` 2개만 허용한다. |
| 길안내 집중 | `NAV-01`에서는 하단 탭을 숨긴다. |
| 평가 표시 시점 | `ARR-01` 진입 즉시 `ARR-02`를 표시한다. |

## 4. 북마크

| 화면 ID | 핵심 기능 | 주요 전환 규칙 | 데이터/정책 |
| --- | --- | --- | --- |
| `BMK-01` | 장소 북마크 목록을 조회하고 상세/길찾기/삭제를 제공한다. | 카드 본문 선택 시 `FAC-01`, `길찾기` 선택 시 `DEST-03` 확인 후 `ROUTE-01`, 탭 전환 시 `BMK-02`로 이동한다. | 사용자 노출 명칭은 `북마크`다. 편집 모드는 삭제만 제공한다. |
| `BMK-02` | 경로 북마크 목록을 조회하고 상세/길안내/삭제를 제공한다. | 카드 본문 선택 시 `ROUTE-02`, `길찾기` 선택 시 `NAV-01`, 탭 전환 시 `BMK-01`로 이동한다. | 경로 북마크의 `길찾기`는 즉시 길안내로 진입한다. 정렬, 전체 선택, 다중 선택은 제공하지 않는다. |

### 4.1 북마크 공통 규칙

| 항목 | 기준 |
| --- | --- |
| 명칭 | `저장`, `Saved` 대신 `북마크`를 사용한다. |
| 데이터 책임 | 북마크 장소와 북마크 경로 모두 서버 데이터가 기준이다. 로컬은 `cache/offline/pending` 보조 역할이다. |
| 상세 연결 | 카드 본문은 상세, CTA는 길찾기 역할을 분리한다. |

## 5. 제보

| 화면 ID | 핵심 기능 | 주요 전환 규칙 | 데이터/정책 |
| --- | --- | --- | --- |
| `REPORT-01` | 제보할 장애물 유형을 선택한다. | 유형 선택 후 `REPORT-02`로 이동한다. | 유형은 `공사/통제`, `계단/단차`, `경사 문제`, `엘리베이터 고장`, `점자블록 문제`, `유도블록 문제`, `시설 파손/노후`, `기타 장애물` 8개다. |
| `REPORT-02` | 제보 위치를 확인하고 조정한다. | 위치 확정 후 `REPORT-03`으로 이동한다. | 위치 확정 방식은 pin drag다. |
| `REPORT-03` | 사진과 설명을 입력하고 제보를 제출한다. | 제출 성공 시 `REPORT-04`로 이동한다. | 사진 첨부는 갤러리/카메라 모두 허용한다. image upload API와 URL 정책은 `BE 확인 필요`다. |
| `REPORT-04` | 제보 접수 완료를 안내한다. | `제보 내역 확인하기`는 `MYP-02`, `홈으로 이동`은 `MAP-01`로 연결한다. | 제보 처리 상태는 사용자 화면에 노출하지 않는다. |

### 5.1 제보 공통 규칙

| 항목 | 기준 |
| --- | --- |
| 인증/계정 연결 | 제보는 사용자 계정과 연결한다. 익명 제보를 기본 정책으로 사용하지 않는다. |
| 데이터 책임 | 제출 이후 제보 이력은 서버 데이터가 기준이다. 작성 중 draft만 로컬에서 임시 보관할 수 있다. |
| 상태 노출 | 운영 내부 상태가 존재하더라도 사용자 화면에는 노출하지 않는다. |

## 6. 마이페이지

| 화면 ID | 핵심 기능 | 주요 전환 규칙 | 데이터/정책 |
| --- | --- | --- | --- |
| `MYP-01` | 프로필 요약, 활동 배지, 사용자 유형 변경, 제보 내역, 앱 정보 및 도움말, 로그아웃을 제공한다. | `사용자 유형 변경`은 `ONB-002`, `제보 내역`은 `MYP-02`, `앱 정보 및 도움말`은 `MYP-03`, 로그아웃 완료 시 `AUTH-001`로 이동한다. | 프로필 필드 매핑, 활동 배지 산정, 알림 설정 노출 여부, 로그아웃 정책은 미정이다. |
| `MYP-02` | 사용자 제보 목록을 제공한다. | 뒤로가기는 `MYP-01`로 복귀한다. | 제보 처리 상태는 목록과 상세에 노출하지 않는다. |
| `MYP-03` | 이용 가이드, 약관/개인정보, 고객센터/1:1 문의 placeholder, 회원탈퇴 동선을 제공한다. | `회원탈퇴` 처리 완료 시 `AUTH-001`로 이동한다. | 고객센터/1:1 문의는 `준비중인 기능입니다.` 메시지로 처리한다. 회원탈퇴 재인증 방식과 데이터 삭제 범위는 `BE 확인 필요`다. |

### 6.1 계정 공통 규칙

| 항목 | 기준 |
| --- | --- |
| 로그아웃 | 토큰 삭제 범위, 온보딩/프로필 상태 유지 여부, 확인 다이얼로그는 미정이다. |
| 회원탈퇴 | 재인증이 필요하며 처리 후 로그인 화면으로 이동한다. 북마크 데이터 삭제, 제보/평가 데이터 유지 여부는 `BE 확인 필요`다. |
| 이용 가이드 | 처음 튜토리얼 화면을 재사용할 수 있다. |

## 7. 데이터 책임 및 저장 위치

| 데이터 영역 | 기준 저장소 | 로컬 역할 | 비고 |

## 8. MVP 제외 또는 후순위

- `SCR-001`~`SCR-003`, `ONB-01`~`ONB-03` 같은 구 온보딩 구조
- production 기준 `비로그인으로 계속`, guest mode, 비로그인 지도/경로/북마크/제보 진입
- 3탭 또는 5탭 후보 구조
- 시각장애 전용 `VIS` 흐름과 LLM UI를 현재 MVP 메인 플로우로 서술하는 정책
- 사용자 노출 명칭으로 `저장`, `Saved`, `자주 가는 길`을 기본 화면명처럼 사용하는 정책
- 북마크 정렬, 전체 선택, 다중 선택
- 제보 처리 상태 화면
- 고객센터/1:1 문의 실제 연결
- 길안내 중도 종료 정책 확정
- `local-first`나 로컬 source of truth를 production 핵심 정책으로 서술하는 방식

## 9. 미확정 항목

| 영역 | 내용 |
| --- | --- |
| 로그인 UX 순서 | 시스템 gate는 `authSession -> onboardingCompleted -> MAP-01`로 고정한다. 다만 `AUTH-001`과 `ONB-001`의 시각적 첫 노출 순서는 최종 UX 확정이 필요하다. |
