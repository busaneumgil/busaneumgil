> 문서일: 2026-05-13  
> Work Lane: FE

## 1. 목적

검색에서 장소를 고르고 경로 설정, 경로 상세 확인, 안내 진행으로 이어지는 흐름을 카카오맵 레퍼런스에 가깝게 정리한다.

이번 문서는 UX 동작과 화면 상태 전환만 고정한다. 색상, 타이포, 아이콘 세부 형태, 간격, 이미지 비율 같은 시각 UI 상세는 다음 단계 문서 또는 구현 계획에서 확정한다.

구현자는 이 문서를 단일 구현 지시서로만 보지 않는다. 실제 수정 시에는 `FE/app`의 현재 navigation, ViewModel, repository handoff, map overlay, route setting 구조를 함께 확인하고, 한 파일의 UX 수정이 검색, 지도, 경로 설정, 길안내, 하단 탭 동작에 미치는 영향을 검토해야 한다.

## 3. 확정된 UX 방향

1. 검색 초기/결과 화면의 프로모션 이미지는 스크롤 콘텐츠 중간에 두지 않고 하단 고정 영역으로 배치한다.
2. 검색 결과에서 장소를 선택하면 단순 지도 홈으로 복귀하지 않는다. 선택 장소가 유지된 지도 미리보기 상태로 진입한다.
3. 선택 장소 지도 상태는 상단 검색바, 중앙 지도, 하단 장소 상세 바텀시트로 구성한다.
4. 장소 상세 바텀시트는 아래로 드래그해도 완전히 사라지지 않고, 장소명과 하단 고정 액션 영역만 남는 접힘 상태로 전환한다.
5. 장소 상세 바텀시트의 최하단에는 접근성/장소 태그와 주요 액션을 고정한다.
6. 주요 액션에는 `출발`과 `도착`을 반드시 포함한다.
7. `출발` 또는 `도착`을 누르면 해당 장소를 경로 설정의 출발지 또는 도착지로 지정하는 흐름으로 이어진다.

### 3.1 UX 명확화 리뷰 결과

| 기존 모호점 또는 문제 | 개선 기준 |
| --- | --- |
| 검색 결과 항목 탭과 지도 미리보기 탭이 다른 의미로 남아 있어 사용자가 다음 흐름을 예측하기 어렵다. | 일반 검색 결과 선택의 기본 동작은 `DEST-03` 장소 선택 지도 상태 진입으로 통일한다. 보조 액션이 필요하면 카드 안의 별도 버튼으로 분리하고, 카드 전체 탭과 같은 결과를 만들지 않는다. |
| `DEST-03`에서 바텀시트를 아래로 내리는 동작이 닫기인지 접힘인지 불명확하다. | 아래 드래그는 접힘, 명시적 닫기 버튼은 선택 장소 해제로 고정한다. 접힘 상태에서도 장소명과 `출발`/`도착`은 사라지지 않는다. |
| `출발`/`도착` 선택 후 기존 반대편 입력값 보존 여부가 암묵적이다. | `RouteEditingTarget.ORIGIN` 또는 `RouteEditingTarget.DESTINATION`만 갱신하고, 반대편 값은 사용자가 직접 바꾸기 전까지 유지한다. |
| 하단 nav 노출 여부가 route map의 `Y`와 상세 UX 요구 사이에서 충돌한다. | `DEST-01`~`DEST-02`는 검색 흐름의 진입 맥락에 따라 하단 nav를 허용할 수 있으나, `DEST-03`은 장소 확인과 출발/도착 지정이 주 작업이므로 하단 nav보다 선택 장소 액션을 우선한다. |
| 프로모션 이미지가 검색 결과 스크롤 중간에 들어가면 결과 비교와 선택을 방해한다. | 프로모션은 정보 리스트가 아니라 하단 고정 보조 영역이다. 키보드 또는 작은 화면에서는 숨김/축소를 허용한다. |

## 4. 용어 정의

| 용어 | 의미 |
| --- | --- |
| 검색 초기 상태 | 사용자가 검색 화면에 진입했지만 아직 검색 결과가 없는 상태 |
| 검색 결과 상태 | 검색어 제출 후 장소 후보 리스트가 표시된 상태 |
| 장소 선택 지도 상태 | 검색 결과 또는 지도 선택으로 특정 장소가 선택되어 지도와 바텀시트가 함께 보이는 상태 |
| 바텀시트 확장 상태 | 장소 상세 정보, 이미지/메타 정보, 태그, 액션을 모두 볼 수 있는 상태 |
| 바텀시트 접힘 상태 | 장소명과 하단 고정 태그/액션 영역만 보이는 최소 노출 상태 |
| 하단 고정 액션 영역 | 바텀시트 내용 스크롤과 무관하게 항상 하단에 남는 태그 및 액션 버튼 영역 |

### 4.1 화면 상태와 전역 상태 분리 원칙

- `DEST-01`과 `DEST-02`는 검색 화면의 입력/결과 상태다.
- `DEST-03`은 검색 화면이 아니라 지도 위 선택 장소 확인 상태다.
- `MAP-01` 기본 지도 홈은 선택 장소가 없는 탐색 상태다.
- `ROUTE-01`은 출발지와 도착지가 준비된 뒤 경로 후보를 비교하는 상태다.
- 검색 결과에서 장소를 눌렀다는 이유만으로 `MAP-01` 기본 홈 또는 `ROUTE-01` 경로 결과로 건너뛰지 않는다.
- 장소 선택 상태는 화면 전환보다 선택 장소 컨텍스트가 우선이다. 장소명, 좌표, 접근성 태그, 진입 맥락, 편집 대상이 함께 보존되어야 한다.

## 5. DEST-01 목적지 검색 UX

### 5.1 화면 목적

사용자가 목적지 또는 출발지로 사용할 장소명을 입력하고 검색을 시작한다.

### 5.2 화면 구성

- 상단에는 검색 입력 영역을 둔다.
- 검색 입력의 문구는 진입 맥락에 따라 달라진다.
  - 도착지 선택 맥락: `도착지 검색`
  - 출발지 선택 맥락: `출발지 검색`
- 경로 설정 중 재검색으로 진입한 경우, 일반적인 `어디로 갈까요?` 문구는 사용하지 않는다.
- 최근 검색어 또는 최근 목적지는 검색 입력 아래에 배치할 수 있다.
- 프로모션 이미지는 화면 하단 고정 영역에 배치한다.

### 5.3 프로모션 이미지 고정 규칙

- 프로모션 이미지는 검색 초기 상태와 검색 결과 상태에서 동일하게 하단 고정 영역으로 취급한다.
- 리스트 스크롤에 따라 이미지가 중간에 끼어 올라오지 않아야 한다.
- 키보드가 열려 화면 높이가 부족한 경우에는 이미지가 입력/결과 조작을 방해하지 않도록 숨김 또는 축소할 수 있다.
- 이미지보다 검색 입력과 검색 결과 선택 가능성이 우선이다.

### 5.4 주요 사용자 행동

| 행동 | 결과 |
| --- | --- |
| 검색어 입력 | 검색어가 입력 필드에 반영된다. |
| 검색 제출 | `DEST-02` 검색 결과 상태로 이동한다. |
| 최근 검색어 선택 | 해당 검색어로 `DEST-02` 검색 결과 상태로 이동한다. |
| 뒤로가기 | 이전 화면으로 복귀한다. |

## 6. DEST-02 검색 결과 선택 UX

### 6.1 화면 목적

사용자가 검색 결과 후보 중 하나를 비교하고 선택한다.

### 6.2 화면 구성

- 상단 검색바는 유지한다.
- 검색 결과 리스트는 장소명, 주소 또는 보조 설명, 접근성 태그를 우선 표시한다.
- 검색 결과가 로딩 중이면 결과 영역에 로딩 상태를 명확히 표시한다.
- 검색 결과가 없거나 실패한 경우, 같은 화면 안에서 빈 상태 또는 오류 상태를 보여준다.
- 프로모션 이미지는 결과 리스트 아래 스크롤 콘텐츠가 아니라 하단 고정 영역에 둔다.
- 검색 결과 카드의 주 터치 영역은 장소 선택으로 동작한다.
- 북마크, 음성 브리핑, 상세 미리보기 같은 보조 액션은 카드 전체 탭과 같은 영역에 섞지 않고 별도 버튼으로 분리한다.

### 6.3 장소 선택 동작

검색 결과 항목을 누르면 아래 동작을 수행한다.

1. 선택한 장소 정보를 보존한다.
2. 지도 카메라를 선택 장소 중심으로 이동할 준비를 한다.
3. `DEST-03` 장소 선택 지도 상태로 전환한다.
4. 전환 후 하단에는 해당 장소의 상세 바텀시트가 열린다.

금지 동작:

- 선택 장소 컨텍스트 없이 `MAP-01` 기본 홈 상태로 복귀하지 않는다.
- 결과 선택 직후 바로 `ROUTE-01`로 이동하지 않는다.
- 장소 선택 후 검색 결과 화면에 머문 채 사용자에게 다음 행동을 다시 추측하게 하지 않는다.
- 검색 결과 카드 전체 탭이 `ROUTE-01`로 직접 이동하지 않는다.
- 선택 장소를 저장하지 않은 상태에서 map route만 pop하거나 top-level map으로 이동하지 않는다.

### 6.4 진입 맥락별 선택 결과

| 진입 맥락 | 결과 |
| --- | --- |
| 지도 홈 검색 | 선택 장소를 지도에서 미리보고, 사용자가 `출발` 또는 `도착`을 고른다. |
| 경로 설정의 출발지 검색 | 선택 장소를 출발지 후보로 지도에서 미리보고, `출발` 액션을 우선한다. |
| 경로 설정의 도착지 검색 | 선택 장소를 도착지 후보로 지도에서 미리보고, `도착` 액션을 우선한다. |

진입 맥락은 검색 route의 표시 문구뿐 아니라 `DEST-03`의 기본 CTA 우선순위에도 영향을 준다. 단, 우선 CTA가 달라지더라도 다른 액션을 완전히 숨기지 않는다. 사용자가 출발지 검색으로 들어왔더라도 실제로는 도착지로 지정할 수 있어야 하며, 반대의 경우도 같다.

## 7. DEST-03 지도 선택 / 장소 상세 바텀시트 UX

### 7.1 화면 목적

검색 결과에서 고른 장소를 지도 위에서 확인하고, 그 장소를 출발지 또는 도착지로 지정한다.

### 7.2 기본 화면 구성

- 상단: 선택 장소명이 들어간 검색바
- 중앙: 선택 장소 중심 지도
- 지도 위: 선택 장소 마커
- 하단: 장소 상세 바텀시트

이 상태에서는 하단 nav를 노출하지 않는다. 사용자의 주 작업은 전역 탭 이동이 아니라 장소 확인과 출발/도착 지정이다.

현재 1차 route map은 `DEST-03`의 하단 탭 여부를 `Y`로 두고 있으나, 이 문서의 작업 기준에서는 카카오맵형 장소 선택 상태를 우선한다. 구현 전에 route map과 충돌을 기록하고, 실제 코드에서는 `DEST-03`을 top-level map 홈과 같은 탭 상태로 취급해 장소 선택 액션이 가려지지 않도록 한다.

### 7.3 바텀시트 상태

#### 확장 상태

확장 상태에서는 장소 상세 확인과 경로 지정이 모두 가능해야 한다.

필수 정보:

- 장소명
- 장소 카테고리 또는 대표 태그
- 주소 또는 위치 보조 정보
- 접근성 태그
- `출발` 액션
- `도착` 액션

선택 정보:

- 평점, 리뷰 수, 영업 상태
- 사진 미리보기
- 북마크, 공유, 전화, 주변 보기 같은 보조 액션

#### 접힘 상태

아래로 드래그하면 바텀시트는 완전히 사라지지 않고 접힘 상태가 된다.

접힘 상태에서 남아야 하는 정보:

- 장소명
- 대표 태그 또는 접근성 태그 요약
- 하단 고정 액션 영역
- `출발` 액션
- `도착` 액션

접힘 상태의 목적은 지도를 더 넓게 보면서도 현재 선택 장소와 핵심 행동을 잃지 않게 하는 것이다.

접힘 상태는 dismiss가 아니다. 접힘 상태에서도 선택 장소 마커, 지도 카메라 기준점, 장소명, 접근성 태그 요약, `출발`/`도착` 액션은 유지한다. 닫기 버튼을 누르기 전에는 선택 장소 컨텍스트를 clear하지 않는다.

### 7.4 하단 고정 액션 영역

바텀시트의 최하단에는 태그와 주요 액션을 고정한다.

고정 영역 요구사항:

- 바텀시트 내부 상세 정보가 스크롤되어도 하단 고정 액션 영역은 화면 하단에 남는다.
- 접힘 상태에서도 동일한 고정 영역이 유지된다.
- `출발`과 `도착`은 항상 사용 가능한 핵심 액션으로 보인다.
- 접근성 태그는 가능한 경우 최대 3개까지 우선순위대로 노출한다.
- 태그가 많으면 `+n` 요약을 사용한다.
- 보조 액션이 필요하면 `북마크`, `공유`, `전화`, `주변 보기`를 추가할 수 있으나, `출발`과 `도착`보다 행동 우선순위가 높아지면 안 된다.

### 7.5 드래그 제스처

| 제스처 | 결과 |
| --- | --- |
| 바텀시트 상단 핸들을 위로 드래그 | 확장 상태로 전환한다. |
| 바텀시트 상세 영역을 아래로 드래그 | 접힘 상태로 전환한다. |
| 접힘 상태에서 장소명 또는 핸들을 탭 | 확장 상태로 전환한다. |
| 닫기 버튼 탭 | 선택 장소 상태를 해제하고 이전 검색 결과 또는 지도 기본 상태로 돌아간다. |

닫기 버튼과 아래 드래그는 다른 동작이다. 아래 드래그는 접힘, 닫기 버튼은 장소 선택 해제로 취급한다.

접근성 동작:

- 핸들은 "장소 상세 접기/펼치기"로 읽혀야 한다.
- 닫기 버튼은 "장소 선택 닫기"로 읽혀야 하며, 핸들의 접기/펼치기 라벨과 혼동되면 안 된다.
- TalkBack 사용자는 드래그 없이도 접힘/확장과 닫기를 각각 실행할 수 있어야 한다.

### 7.6 출발 / 도착 액션

| 액션 | 결과 |
| --- | --- |
| `출발` 선택 | 현재 장소를 경로 설정의 출발지로 지정한다. |
| `도착` 선택 | 현재 장소를 경로 설정의 도착지로 지정한다. |

액션 후 기대 흐름:

- 출발지와 도착지가 모두 준비되면 `ROUTE-01` 경로 지도 / 경로 탐색 결과로 이동한다.
- 하나만 준비된 경우에는 경로 설정 화면에서 누락된 입력란을 명확히 보여준다.
- 경로 설정 중 특정 입력란을 수정하러 들어온 경우에는 선택한 값만 갱신하고 기존 반대편 입력값은 유지한다.
- `출발`은 `RouteEditingTarget.ORIGIN`, `도착`은 `RouteEditingTarget.DESTINATION`에 대응한다.
- `DEST-03`에서 액션을 누를 때만 `DestinationSelectionRepository`의 선택값을 확정 갱신한다.
- 검색 결과 선택 직후에는 route setting 값을 확정하지 않고 preview 상태로 둔다.

## 8. 상태 전환 요약

```text
DEST-01 검색 초기
  -> 검색 제출
DEST-02 검색 결과
  -> 장소 결과 선택
DEST-03 장소 선택 지도 상태
  -> 바텀시트 확장 / 접힘 전환
  -> 출발 또는 도착 지정
ROUTE-01 경로 지도 / 경로 탐색 결과
```

진입 맥락 포함 전환:

```text
ROUTE-01 또는 경로 설정 입력란
  -> 출발지/도착지 재검색
DEST-01 검색 초기
  -> DEST-02 검색 결과
  -> DEST-03 장소 선택 지도 상태
  -> 출발/도착 확정
ROUTE-01로 복귀 또는 경로 설정 입력 상태 갱신
```

예외 전환:

```text
DEST-03 장소 선택 지도 상태
  -> 닫기
이전 검색 결과 또는 지도 기본 상태
```

뒤로가기 정책:

- `DEST-02`에서 뒤로가기는 `DEST-01`로 돌아가되 직전 검색어 입력 상태를 보존할 수 있다.
- `DEST-03`에서 시스템 뒤로가기는 닫기 버튼과 동일하게 선택 장소 상태 해제를 우선한다.
- `DEST-03`에서 바텀시트 접힘 상태인 경우, 첫 번째 뒤로가기는 확장 상태 복귀가 아니라 선택 장소 해제로 처리한다. 접힘은 지도 탐색 보조 상태이지 별도 back stack이 아니다.

## 9. 구현 시 고려사항

### 9.1 현재 구현과 맞춰야 할 지점

- 현재 검색 결과 클릭은 지도 미리보기 이벤트로 이어질 수 있다. 이 흐름을 `DEST-03`의 정식 UX로 고정한다.
- 검색 route가 현재 하단 탭의 지도 탭으로 취급될 수 있으므로, `DEST-01`~`DEST-03`에서는 하단 nav 노출 정책을 재검토해야 한다.
- 장소 상세 바텀시트는 dismiss와 collapse를 분리해야 한다.
- 기존 장소 상세 바텀시트가 아래 드래그를 dismiss로 처리한다면, 접힘 상태를 별도 상태로 추가해야 한다.
- 출발/도착 액션은 `RouteEditingTarget.ORIGIN`, `RouteEditingTarget.DESTINATION`과 연결한다.
- 현재 코드에는 `SearchUiEvent.NavigateToRouteSetting`과 `SearchUiEvent.NavigateToMapPreview`가 분리되어 있다. UX 개선 시 결과 카드 기본 탭이 어느 이벤트를 내야 하는지 명확히 정하고, 기존 보조 액션 흐름이 의도치 않게 바뀌지 않는지 확인한다.
- `MapViewModel`은 `DestinationPreviewRepository`를 통해 선택 장소 미리보기를 받을 수 있다. 이 preview 상태를 `DestinationSelectionRepository`의 확정 선택값과 혼동하지 않는다.
- `FacilityDetailBottomSheetShell`의 현재 드래그 동작이 dismiss 중심이면, 이를 바로 삭제하지 말고 facility marker, map tap, destination preview 세 진입 경로가 각각 어떤 접힘/닫기 정책을 가져야 하는지 분리한다.

### 9.2 UX 우선순위

1. 검색 결과 선택 후 선택 장소 컨텍스트 유지
2. 장소 상세 바텀시트의 확장/접힘 상태 분리
3. 접힘 상태에서도 장소명과 출발/도착 액션 유지
4. 프로모션 이미지 하단 고정
5. 경로 설정 진입 맥락에 맞는 검색 문구 적용

### 9.3 구현 영향 범위 검토 원칙

FE 코드 개선은 이 문서의 구현 계획만 보고 단일 파일을 고치는 방식으로 진행하지 않는다. 수정 대상 파일에 의존하거나 그 파일과 상태를 주고받는 다른 파일을 함께 읽고, 기존 다른 동작이 의도와 다르게 바뀌지 않는지 확인한다.

필수 검토 범위:

| 수정 영역 | 함께 확인할 연관 영역 | 회귀 위험 |
| --- | --- | --- |
| `SearchScreen`, `SearchViewModel`, `SearchContract` | `MainNavGraph`, `SearchRoute`, `DestinationPreviewRepository`, `DestinationSelectionRepository` | 검색 결과 탭이 기존 route setting, voice input, briefing, low-vision bookmark 흐름을 깨는 위험 |
| `MapViewModel`, `MapContract` | `MapRoute`, `MapScreen`, `MapViewport`, `FacilityDetailBottomSheetShell`, `RecentDestinationBottomSheetShell` | 선택 장소 preview, 시설 상세, 지도 탭, 최근 목적지 바텀시트가 같은 상태를 덮어쓰는 위험 |
| `FacilityDetailBottomSheetShell` | facility marker 탭, map tap 상세, destination preview, bookmark action, route setting 진입 | dismiss를 collapse로 바꾸면서 기존 시설 상세 닫기, 북마크, 지도 핀 clear 동작이 꼬이는 위험 |
| `RouteSettingViewModel`, `RouteSettingContract`, `RouteSettingEntryRoute` | `RouteEditingTarget`, `DestinationSelectionRepository`, search 재진입 route | 출발지/도착지 중 하나만 바꿔야 하는데 반대편 값까지 초기화되는 위험 |
| `AppNavHost`, `MainNavGraph`, `TopLevelDestination` | top-level map alias, search route alias, bottom tab 표시 조건 | `DEST-03`을 map home으로 잘못 취급해 하단 탭 또는 home reentry reset이 선택 장소를 지우는 위험 |

수정 전 체크:

- 변경하려는 state/event가 한 화면 전용인지, repository/shared ViewModel을 통해 다른 화면과 공유되는지 확인한다.
- `selectedDestination`, `selectedDestinationPreview`, `selectedMapTapDetail`, `selectedFacilityDetail`의 역할을 섞지 않는다.
- route pop, top-level navigate, savedStateHandle reset이 선택 장소 preview를 지우는지 확인한다.
- 하단 nav 표시 조건을 바꾸면 `MAP-01`, `DEST-01`, `DEST-02`, `DEST-03`, `ROUTE-01`, `NAV-01` 각각의 노출 결과를 표로 확인한다.
- 접근성 라벨은 `FE/docs/2026-04-24_부산이음길_FE_접근성_정보_라벨_가이드.md`의 고정 문구와 우선순위를 사용한다.

수정 후 확인:

- 검색 결과 선택 -> 장소 지도 preview -> 접힘/확장 -> 출발/도착 지정 플로우가 동작한다.
- 검색 결과에서 보조 액션을 눌렀을 때 기존 북마크, 음성 브리핑, 저시력자 북마크 흐름이 유지된다.
- 지도 홈에서 시설 마커를 탭했을 때 기존 시설 상세, 북마크, 길찾기 흐름이 유지된다.
- 최근 목적지에서 길찾기를 눌렀을 때 기존 경로 설정 흐름이 유지된다.
- route setting에서 출발지 또는 도착지만 재검색했을 때 반대편 값이 유지된다.
- 시스템 뒤로가기, 닫기 버튼, 바텀시트 아래 드래그가 서로 다른 의미로 동작한다.

## 10. Acceptance Criteria

- `DEST-01`에서 검색 초기 프로모션 이미지는 하단 고정 영역에 표시된다.
- `DEST-02`에서 검색 결과가 길어져도 프로모션 이미지는 리스트 중간에 끼지 않는다.
- `DEST-02`에서 장소를 선택하면 선택 장소가 표시된 `DEST-03` 지도 상태로 이동한다.
- 장소 선택 후 선택 장소명, 마커, 바텀시트가 함께 표시된다.
- 바텀시트를 아래로 드래그하면 닫히지 않고 접힘 상태가 된다.
- 접힘 상태에서도 장소명과 하단 고정 액션 영역이 보인다.
- 하단 고정 액션 영역에는 태그와 `출발`, `도착` 액션이 유지된다.
- 닫기 버튼을 눌렀을 때만 장소 선택 상태가 해제된다.
- `출발`을 누르면 해당 장소가 출발지로 지정된다.
- `도착`을 누르면 해당 장소가 도착지로 지정된다.
- `DEST-01`~`DEST-03`에서는 하단 nav가 핵심 작업을 방해하지 않는다.
- 검색 결과 카드의 기본 탭은 선택 장소 preview로 이어지고, route setting 확정은 `출발`/`도착` 액션 이후에만 일어난다.
- 경로 설정 중 출발지 또는 도착지를 수정해도 사용자가 수정하지 않은 반대편 입력값은 유지된다.
- 바텀시트 접힘/확장/닫기 동작은 facility marker, map tap, destination preview 진입 경로별로 의도한 상태만 변경한다.
- 이 문서 기반 코드 수정은 수정 파일과 연관 파일의 상태/event/navigation 의존성을 함께 검토했다는 구현 기록 또는 PR 설명을 남긴다.
- 기존 지도 홈, 시설 상세, 최근 목적지, 북마크, 음성 검색, 경로 설정, 길안내 진입 동작이 이번 UX 수정으로 의도치 않게 회귀하지 않는다.

## 12. Open Questions

1. 장소 상세 바텀시트의 보조 액션은 MVP에서 `북마크`, `공유`, `전화`, `주변 보기`까지 포함할지, 아니면 `출발`/`도착` 중심으로 최소화할지 결정이 필요하다. 단, 어떤 결정을 하더라도 `출발`/`도착`보다 보조 액션이 우선되면 안 된다.
2. `출발` 또는 `도착` 선택 후 바로 `ROUTE-01`로 이동할지, 경로 설정 입력 화면을 한 번 더 보여줄지 진입 맥락별 정책 확인이 필요하다. 이 정책은 `DestinationSelectionRepository`의 기존 selection handoff와 충돌하지 않아야 한다.
3. 닫기 버튼을 눌렀을 때 `DEST-02` 검색 결과로 돌아갈지, `MAP-01` 지도 기본 상태로 돌아갈지 진입 경로별 정책 확인이 필요하다. 검색 결과에서 진입한 경우에는 직전 결과 복귀를 우선 검토하고, 지도 직접 선택에서 진입한 경우에는 지도 기본 상태 복귀를 우선 검토한다.
4. `DEST-03`의 하단 nav 숨김 정책을 1차 route map 문서에 반영할지, 이 문서의 UX 개선 범위 안에서만 예외로 둘지 결정이 필요하다.
