# 이재호 기여와 근거 — 부산이음길

> 작성일: 2026-09-14\
> 성격: 기존 공개 문서·코드·커밋을 바탕으로 사후 정리한 설명 문서입니다. 프로젝트 당시 존재한 산출물처럼 사용하지 않습니다.

[README로 돌아가기](../README.md)

## 역할과 범위

이재호는 7인 팀의 팀원으로 Frontend와 문서 작업을 맡았습니다. 개인 기여는 문서 정합성, 글자 크기 설정, 승인 제보의 지도 표시로 한정해 설명합니다. 사용자 유형별 제품 흐름은 팀의 기획·디자인·구현 결과이며, 경로 계산과 공간 데이터 구축은 Backend·AI·Data 담당 작업입니다.

## 문서·구현·검증 연결

### 1. 화면과 데이터 상태를 명세에 맞췄습니다

PRD·기능명세·화면명세에 제보의 사진 업로드 방식, 처리 상태 노출 위치, 승인된 공개 제보만 지도에 표시하는 조건을 반영했습니다. 이어서 2026-05-20 요구사항명세서에서 구현된 화면과 Backend·운영 데이터 확인이 필요한 항목을 분리했습니다.

- 원본 문서: [요구사항명세서](PRD/2026-05-20_요구사항명세서.md), [기능명세서](PRD/2026-04-14_기능명세서.md), [화면명세서](<기획/2026-04-09_화면명세서.md>)
- 공개 커밋: [기획·기능명세 기준 최신화](https://github.com/busaneumgil/busaneumgil/commit/75b2592c83c7a8731b7b50751863f9e83f141e1b), [요구사항명세서와 기능 정합성 최신화](https://github.com/busaneumgil/busaneumgil/commit/88379f0f570a4a653927017e4f0f293294ca8c65)
- 확인된 결과: 사진은 선택이며 최대 5장, 처리 상태는 제보 이력에서 확인, 지도에는 승인된 공개 제보만 표시한다는 계약이 문서에 남아 있습니다.
- 한계: 요구사항명세서는 승인 정책과 지도 반영 기준, 운영 데이터 범위를 Backend 확인 대상으로 남깁니다.

### 2. 글자 크기 설정을 앱 전역 흐름에 연결했습니다

`기본`, `크게`, `아주 크게` 선택값을 저장하고 앱 테마에 적용하는 기반, 설정 화면, 마이페이지 재진입 경로를 구현했습니다. 글자를 키웠을 때 마이페이지 바로가기 레이아웃이 대응하도록 후속 수정했습니다.

- 테스트: [TextSizePreferenceRepositoryTest](../FE/app/src/test/java/com/ssafy/e102/eumgil/data/repository/TextSizePreferenceRepositoryTest.kt), [TextSizeSettingViewModelTest](../FE/app/src/test/java/com/ssafy/e102/eumgil/feature/textsize/TextSizeSettingViewModelTest.kt)
- 공개 커밋: [글자 크기 설정 공통 기반](https://github.com/busaneumgil/busaneumgil/commit/9537c3e08ff5c7c4582db394c8063ed4627a63a5), [마이페이지 진입 연결](https://github.com/busaneumgil/busaneumgil/commit/54f03e86dd1cd3271a5ab30945adb3026c4aec9d), [확대 대응 수정](https://github.com/busaneumgil/busaneumgil/commit/2bf39612d8e18fa85d0a56a82e401720de1f6666)
- 확인된 결과: 선택값 저장과 화면·테마 연결을 코드와 단위 테스트에서 확인했습니다.
- 한계: 이동약자 대상 접근성 사용성 시험을 수행했다는 공개 기록은 확인하지 못했습니다.

### 3. 승인 제보를 시설 마커와 구분해 표시했습니다

승인 제보용 마커 레이어를 시설 마커와 분리하고, 선택한 제보의 내용을 여는 전용 하단 패널을 연결했습니다. 화면 표시와 API 연동 경계를 다룬 작업이며, 관리자 승인 정책과 공간 데이터 구축 전체를 개인 기여로 포함하지 않습니다.

- 구현: [KakaoMapViewport](../FE/app/src/main/java/com/ssafy/e102/eumgil/feature/map/component/KakaoMapViewport.kt), [MapRoute](../FE/app/src/main/java/com/ssafy/e102/eumgil/feature/map/MapRoute.kt), [ApprovedReportBottomSheetShell](../FE/app/src/main/java/com/ssafy/e102/eumgil/feature/map/component/ApprovedReportBottomSheetShell.kt)
- 테스트: [KakaoApprovedReportMarkerBindingsTest](../FE/app/src/test/java/com/ssafy/e102/eumgil/feature/map/component/KakaoApprovedReportMarkerBindingsTest.kt), [MapScreenApprovedReportPolicyTest](../FE/app/src/test/java/com/ssafy/e102/eumgil/feature/map/MapScreenApprovedReportPolicyTest.kt)
- 인계 문서: [승인 제보 지도 API 인계](API/2026-05-19-approved-report-map-api-handoff.md)
- 공개 커밋: [마커 레이어 분리](https://github.com/busaneumgil/busaneumgil/commit/f8db847606c4d06ae608e6688fbfa00c0dace033), [전용 하단 패널 연결](https://github.com/busaneumgil/busaneumgil/commit/52e952dc34c10c83e6c8243cb2d06e46a0d2d18a), [통합 검증 오류 수정](https://github.com/busaneumgil/busaneumgil/commit/4f4bac8e11323d6f37ae9249c13a0b2b473d2687)
- 한계: 운영 데이터의 범위와 최신성, 실제 위험도 반영 기준은 Frontend 코드만으로 검증할 수 없습니다.

## 팀 작업과 분리한 항목

- 사용자 유형별 온보딩과 별도 화면군은 팀 제품 흐름입니다. 이재호의 문서·일부 Android 구현만 개인 범위로 둡니다.
- `안전한 길` 경로 계산, GraphHopper 그래프, PostGIS 공간 데이터 구축은 Backend·AI·Data 팀 작업입니다.
- 제보 승인 정책과 관리자 기능, 서버의 공개 데이터 판정은 개인 Frontend 작업으로 주장하지 않습니다.
- 시연 영상은 앱 화면 동작의 근거이며 현장 안전성이나 접근성 사용성 시험의 근거가 아닙니다.

## 확인 가능한 결과와 남은 검증

확인 가능한 결과는 최신 요구사항 문서, 글자 크기 설정 코드와 단위 테스트, 승인 제보 지도 UI 코드와 테스트, 공개 커밋입니다. 이번 사후 정리에서는 앱 빌드·실기기 시연·현장 검증을 다시 수행하지 않았습니다.

후속 검증이 필요합니다.

- 이동약자 참여 사용성 시험: 사용자 유형별 흐름, 글자 크기, 음성·지도 정보의 실제 사용 가능성
- 현장 경로 검증: `안전한 길` 후보가 부산의 계단·경사·단차를 실제로 피하는지 비교
- 운영 데이터 검증: 승인 제보의 최신성, 공개 조건, 지도 반영 지연과 오류 상태
