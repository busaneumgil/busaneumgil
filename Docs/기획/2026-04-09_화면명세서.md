## 1. 전역 정책

### 1.1 앱 진입 Gate

```text
앱 실행
  -> authSession 확인
  -> authSession 없음: AUTH-001
  -> authSession 있음 + onboardingCompleted=false: ONB-001 또는 미완료 온보딩 단계
  -> authSession 있음 + onboardingCompleted=true: MAP-01
```

| 분기 | 조건 | 이동 화면 | 비고 |
| --- | --- | --- | --- |
| 인증 없음 | 저장된 세션 없음 또는 refresh 실패 | `AUTH-001` | 로그인 제공자 범위와 세션 만료 안내는 추가 확인 필요 |
| 온보딩 미완료 | 인증 완료, 온보딩 미완료 | `ONB-001` 또는 마지막 미완료 단계 | 사용자 유형 등 초기 설정은 온보딩에서 수집한다. 재개 정책은 구현 시 결정 필요 |
| 진입 완료 | 인증, 온보딩 모두 완료 | `MAP-01` | 홈 탭 활성 |

`AUTH-001`은 production 필수 로그인 화면이며 `비로그인으로 계속`, guest mode, 로그인 없이 지도/경로/북마크/제보 진입은 허용하지 않는다.

### 1.2 사용자 용어

| 구분 | 기준 |
| --- | --- |
| 상위 사용자 용어 | `보행약자` |
| 온보딩/설문 세부 이동 특성 | `휠체어 사용자 (전동)`, `휠체어 사용자 (수동)`, `기타 보행약자` |
| 장애등급 | 온보딩 필수 단계에서 제거한다. 프로필 필드 또는 서버 스키마 유지 여부는 `BE 확인 필요`다. |
| 금지/주의 | 과거 문서의 시각장애 전용 메인 온보딩, `SCR-001`~`SCR-003`, `ONB-01`~`ONB-03` 구조는 최신 MVP 필수 단계로 보지 않는다. 후속 접근성 확장 후보로만 분리한다. |
| 서버 매핑 | 사용자 유형 3개 값과 기존 `disabilityType`, `disabilityGrade` 필드의 매핑 방식은 `BE 확인 필요`다. |

| 숨김 | `AUTH-001`, `ONB-001`~`ONB-005`, `FAC-01` overlay, `ROUTE-01`, `ROUTE-02`, `NAV-01`, `ARR-02` overlay, `VIS-01`~`VIS-04` 후보 |

| 항목 | 기준 |
| --- | --- |
| 읽기 순서 | 화면 제목, 설명/상태, 주요 입력 또는 카드, 하단 CTA 순서 |
| 선택 상태 | chip, card, segmented control은 선택/미선택 상태를 TalkBack에서 알 수 있어야 한다. |

## 3. 화면 상세 명세

### AUTH-001 로그인

| 항목 | 내용 |
| --- | --- |
| 화면 목적 | 인증 세션이 없는 사용자가 소셜 로그인으로 서비스 세션을 생성한다. |
| 진입 조건 | 앱 시작 시 authSession 없음, refreshToken 재발급 실패, 로그아웃 완료, 회원탈퇴 완료 |
| 하단 탭 | 숨김 |
| 디자인 상태 | 최종 Figma 디자인 추가 필요. 생산 화면에는 `비로그인으로 계속` CTA를 두지 않는다. |

| 영역 | 구성 |
| --- | --- |
| 브랜드 | 서비스 로고, 서비스명, 간단한 서비스 설명 |
| 로그인 버튼 | 카카오/네이버/구글 provider별 로그인 버튼 |
| 상태 영역 | 기본, 소셜 로그인 진행 중, provider 오류, 서버 오류, 네트워크 오류 |
| 접근성 | 제공자명과 로그인 동작을 버튼 라벨로 명확히 전달 |

| 액션 | 조건 | 결과 |
| --- | --- | --- |
| 소셜 로그인 선택 | provider 사용 가능 | 로그인 진행 상태 표시 |
| 로그인 성공 | 온보딩 미완료 | `ONB-001` 또는 온보딩 미완료 단계 이동 |

## 4. 후속 접근성 확장 후보

`VIS-01`~`VIS-04` 성격의 시각 지원 전용 흐름은 삭제하지 않고 후속 접근성 확장 후보로 둔다. 현재 MVP 핵심 화면명세의 확정 상세 화면은 아니다.

| 화면 후보 | 목적 | 상태 |
| --- | --- | --- |
| `VIS-01` 대화형 목적지 검색 | 음성 중심 목적지 입력 | mockup-only / 후속 확장 |
| `VIS-02` 목적지 확인 | 음성 인식 결과 확인 | mockup-only / 후속 확장 |
| `VIS-03` 경로 브리핑 | 경로 요약 음성 브리핑 | mockup-only / 후속 확장 |
| `VIS-04` 시각장애 안내 진행 | 큰 글씨/음성 중심 길안내 | mockup-only / 후속 확장 |

| 적용 원칙 |
| --- |
| MVP의 사용자 유형 기준과 섞지 않는다. |
| STT/TTS, 큰 글씨, 음성 중심 UI는 별도 접근성 확장 정책과 BE/기기 기능 확인 후 설계한다. |

## 7. MVP 제외 또는 후순위

- 알림함, 공지함, 메시지 inbox 화면은 MVP에서 생성하지 않는다.
- `비로그인으로 계속` 또는 게스트 핵심 기능 진입은 production에 포함하지 않는다.
- `SCR-001`~`SCR-003`, `ONB-01`~`ONB-03` 같은 구 온보딩 구조는 사용하지 않는다.
- 3탭 또는 5탭 후보 구조는 사용하지 않고 `홈/북마크/제보/마이페이지` 4탭만 유지한다.
- 별도 최근 목적지 전체 목록 화면은 만들지 않고 북마크 화면으로 연결한다.
- 사용자 노출 용어로 `저장`, `Saved`, `게스트 모드`, `비로그인 핵심 기능`을 사용하지 않는다.
- 북마크 정렬, 전체 선택, 다중 선택은 제공하지 않는다.
- 제보 처리 상태 화면은 제공하지 않는다.
- 고객센터/1:1 문의 실제 연결은 제공하지 않고 `준비중인 기능입니다.` 메시지만 표시한다.
- 길안내 중도 종료 정책은 이번 MVP에서 확정하지 않는다.
- 접근성 필터 `더보기` 포함 항목은 미정이다.
- `local-first`나 로컬 source of truth 표현은 production 핵심 정책으로 사용하지 않는다.
- 시각 지원 전용 `VIS-01`~`VIS-04` 흐름은 후속 접근성 확장 후보로 둔다.
