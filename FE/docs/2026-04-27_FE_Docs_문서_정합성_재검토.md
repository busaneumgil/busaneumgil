신규 디자인과 로그인 필수 정책이 반영된 뒤, `FE/Docs` 문서들 사이에 남아 있는 화면 ID, 화면명, 하단 탭, 저장/북마크 명칭, 제보 플로우, 접근성 모드, local-first 정책 충돌을 다시 확인한다.

### 4.3 제보 플로우 ID 충돌

| 항목 | 내용 |
| --- | --- |
| 최신 기준 | `REPORT-01` 장애물 유형 선택, `REPORT-02` 위치 확인, `REPORT-03` 상세 정보 입력, `REPORT-04` 제보 완료 |
| 충돌 기준 | 라우트 맵은 `REPORT-01`을 단일 작성 화면, `REPORT-02`를 길안내 중 제보 바텀시트로 정의 |
| 영향 | 제보 route, completion route, 제보 내역 연결, `MYP-02` 진입 규칙 |
| 판단 | 최신 디자인 기준 단계형 플로우를 우선한다. 길안내 중 quick report는 별도 overlay ID로 재분리하는 편이 안전하다. |

### 4.4 경로 화면 ID 의미 충돌

| 항목 | 내용 |
| --- | --- |
| 최신 기준 | `ROUTE-01` 경로 지도/탐색 결과, `ROUTE-02` 경로 상세 정보, `NAV-01` 길안내 진행 |
| 충돌 기준 | 라우트 맵의 `ROUTE-01`은 기존 코드 route `route_setting` 중심의 경로 설정 단일 화면 |
| 영향 | route mapping, 화면명세서, ViewModel handoff, 경로 상세 진입 규칙 |
| 판단 | 라우트 맵에서 현재 코드 route와 목표 화면 ID를 분리해 표기해야 한다. `route_setting`은 구현 route key로 남기고, 사용자 화면 ID는 최신 디자인 기준으로 개정한다. |

### 4.5 시각장애 모드 / VIS 플로우 위치

| 항목 | 내용 |
| --- | --- |
| 최신 기준 | 서비스 상위 사용자 용어는 `보행약자`이며, 목적지 설정에는 `휠체어 사용자 (전동/수동)`, `기타 보행약자` 세부 설문이 존재 |
| 충돌 기준 | 디자인 컨벤션과 라우트 맵에 `시각장애 모드`, `VIS-01`~`VIS-04` 전용 플로우가 남아 있음 |
| 영향 | 사용자 유형 매핑, TTS 기능 범위, 접근성 확장 화면 우선순위 |
| 판단 | `VIS-*`는 삭제하지 않는다. 다만 최신 MVP 메인 플로우가 아니라 후속 접근성 확장 또는 별도 모드 후보로 명시한다. |

### 4.6 local-first 표현 충돌

| 항목 | 내용 |
| --- | --- |
| 최신 기준 | 로그인 필수, 북마크/자주 가는 길은 로그인 사용자 서버 데이터가 기준, 로컬 저장은 cache/offline/pending 보조 |
| 충돌 기준 | sprint backlog 문서의 `local-first`, `서버 의존 없이`, `로컬 기준으로 닫는다` 표현 |
| 영향 | 현재 구현 정책, API 연동 우선순위, Repository 기준 |
| 판단 | sprint backlog는 과거 작업 이력으로 유지 가능하다. 단, 현재 기준 문서나 화면명세서에서 production 정책으로 인용하면 안 된다. |

## 7. 최종 반영 기준

| 항목 | 최종 기준 |
| --- | --- |
| 앱 진입 | `authSession -> profileCompleted -> onboardingCompleted -> main` |
| 인증 화면 | `AUTH-001` 로그인, `AUTH-002` 프로필 설정 / 회원가입 완료 |
| 온보딩 | `ONB-001`~`ONB-005` 5단계, 서비스 소개는 3페이지 이상 |
| 사용자 용어 | 상위 용어는 `보행약자`, 세부 이동 특성은 `휠체어 사용자`, `기타 보행약자` |
| 권한 | 위치 권한은 필수, 마이크 권한은 STT 장소 검색 사용 시점 요청, 알림은 MVP 제외 또는 후순위 |
| 약관 | 약관 전문은 노션 웹뷰로 표시 |
| 메인 탭 | `홈 / 북마크 / 제보 / 마이페이지` 4탭 |
| 지도 홈 | `MAP-01`, 마이크 아이콘은 STT 기반 장소 검색, 최근 목적지 전체보기는 북마크 화면 연결 |
| 목적지 설정 | `DEST-01`~`DEST-04`를 별도 화면 ID로 유지 |
| 검색 결과 선택 | 결과 카드 선택 후 항상 `DEST-03` 지도 바텀시트 확인을 거침 |
| 경로 | `ROUTE-01` 경로 지도, `ROUTE-02` 경로 상세 정보 |
| 경로 옵션 | `안전한 길`, `최단거리` 2개 카드 세로 나열 |
| 경로 상세 진입 | 옵션 카드 선택은 선택 상태 변경, 카드 우측 상단 화살표로 상세 진입 |
| 길안내 | `NAV-01`, 도착 완료 시 `ARR-01`, 경로 이탈 시 재검색/재탐색 |
| 도착/평가 | `ARR-01` 진입 즉시 `ARR-02` 자동 표시, X 버튼으로 평가 건너뛰기 |
| 평가 API | 평가 저장 API는 신규 예정 API 또는 추후 구현 항목으로 명시 |
| 북마크 | `BMK-01` 장소 탭, `BMK-02` 경로 탭. 과거 저장 계열 사용자 노출명은 `북마크`로 통일 |
| 북마크 편집 | 삭제 기능만 제공. 정렬, 전체 선택, 다중 선택은 제공하지 않음 |
| 북마크 카드 | 카드 본문 선택 시 상세 화면 이동. 북마크 경로 `길찾기`는 `NAV-01` 즉시 진입 |
| 제보 | `REPORT-01` 유형 선택, `REPORT-02` 위치 확인, `REPORT-03` 상세 입력, `REPORT-04` 완료 |
| 제보 유형 | 공사/통제, 계단/단차, 경사 문제, 엘리베이터 고장, 점자블록 문제, 유도블록 문제, 시설 파손/노후, 기타 장애물 |
| 제보 위치/사진 | pin drag 제공, 갤러리/카메라 모두 허용, imageUrl 선업로드 방식. 실제 URL/API 상세는 추후 구현 |
| 제보 인증/내역 | 제보는 사용자 계정과 연결. 완료 CTA는 `MYP-02` 목록 연결. 처리 상태는 노출하지 않음 |
| 마이페이지 | `MYP-01` 홈, `MYP-02` 제보 내역, `MYP-03` 앱 정보 및 도움말 |
| 사용자 유형 변경 | `MYP-01`의 사용자 유형 변경은 `ONB-002`로 이동 |
| 회원탈퇴 | 재인증 필요, 제보/평가 데이터 미삭제, 북마크 데이터 삭제, 처리 후 로그인 화면 이동 |
| 앱 정보/도움말 | 이용 가이드는 처음 튜토리얼 내부 화면 재사용, 약관/개인정보는 웹뷰, 고객센터/1:1 문의는 `준비중인 기능입니다.` 메시지 |
